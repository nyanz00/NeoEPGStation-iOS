# 通常字幕のWebレイアウト移植

## 修正範囲と成功条件

ビルド346のlibass背景近似では、空白・装飾境界の黒帯の切れ目、余白、ルビ接続条件がWebと異なった。Aetherは黒い余白を含むコンテナ全体へ字幕画像を引き伸ばしており、右パネルを開くと文字の縦横比も崩れた。

- `CanvasSubtitleLayout.ts`の通常字幕の解析・文字送り・改行・行配置・衝突回避・半透明背景矩形・ルビ接続・レイヤー順を`NeoCaptionLayout.swift`へ移植する。字幕内のフォント名はWeb同様に使用せず、iOSの日本語フォントチェーンを使用する。
- 文字の計測・描画はCoreText、背景矩形の和集合はCoreGraphicsで描く。libassのBorderStyle 3画像は使用しない。VLCとAetherは同じ橋渡しを使い、画面/PiP合成への受け渡しは維持する。TS/ライブARIBと実況コメントは対象外。
- Aetherの字幕を映像のaspect-fit矩形へ配置し、パネル開閉で縦横比を変えない。字幕画像は映像座標のまま保持し、コンテナの幅と高さに別々に伸縮しない。
- 全字幕の画像を先行生成しない。イベント検索は終了時刻の単調prefix indexを使い、文字計測を再利用する。行レイアウトの保持は表示中イベントだけ、画像は静止キューの変更または縦横比変更まで再利用する。

## 比較方法

`tests/captions/make-web-oracle.mjs`は開発時に本体Webソース自体を実行し、同一の決定的文字メトリクスで期待する背景矩形・文字座標・サイズ・色・透明度を保存する。Nodeはテスト用でありアプリには含めない。`web-oracle.json`には元ソースのSHA-256と、装飾境界、空白、ルビと別時間の字幕の同時表示、複数レイヤー、拡縮、移動・フェード、折返し・改行、結合文字の45条件を含む。FoundationのSwift実装と全描画命令を照合する。

実アプリの字幕専用シミュレーター試験で、背景の画素・空白部分の連続性・同時字幕がある場合のルビ接続・レイヤー順・字幕オフ・Aetherパネル前後の表示矩形と画像再利用・PiP合成先への受け渡しを確認する。今回と無関係な一覧/Annict/開始応答時間/全再生試験は追加しない。

CoreTextとブラウザーCanvasの字形ラスタライズ差をピクセル単位の同一性とは主張しない。比較対象は同じ解析とレイアウト規則であり、実機での実録画・PiPバックグラウンド再生とは区別して結果を報告する。

## 確認結果

ビルド347（アプリソース`8fdc5ce`、Actions `42294259154`）で実機・シミュレーター両SDKのビルド成功。Web本体から生成した45条件の比較とSRTの座標面・消去境界がすべて一致した。実アプリの字幕専用試験はiPhone/iPadとも11/11成功し、パネル開閉前後のaspect-fit矩形、空白と装飾をまたぐ背景の画素、別時刻の字幕が同時にある場合のルビ接続、半透明背景の重複、レイヤー順、画面/PiP合成先への受け渡しと消去を確認した。保存した字幕・パネル前後の画像も確認した。

Actions全体も成功。今回の実行で一覧・Annict・ナビゲーション・全再生経路の試験は実行していない。実録画での実機再生・バックグラウンドPiP確認は残る。IPAのソースコミット・ビルド番号・アーカイブとファイルのダイジェストを照合した。IPAは`NeoEPGStation-build347.ipa`、SHA-256は`825192d47a6e20b338201ade20a6ecdaa50fb715582a1acf2ee8b68c768c89e2`。
