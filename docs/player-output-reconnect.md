# 映像復旧の確認と通信の再接続

## 変更範囲

1. スリープ復帰後の映像復旧は、表示キューの整理、映像トラックだけの再起動、現在の再生位置からの入力復旧の順に行う。トラックの選択完了だけでは復旧成功とせず、表示予定時刻が現在に近い、異なる画像が実際に届くことを確認する。復旧段階ごとに期限を設け、入力の再読み込みは一度だけに制限する。一時停止・バッファリング中は期限を消費しない。
2. 新しく作られた映像出力も画素の低頻度サンプリングを開始する。出力の識別子、画像の変化、到着・表示予定時刻、レイヤーのエラーに加え、VLC自身の映像／音声の復号数、表示・欠落画像数を診断へ記録する。最初に映像が停止する原因が復号側か表示側かを切り分けるための変更であり、実機での根本原因を特定済みとは扱わない。
3. 縦画面で上へスワイプ中、動画とその上に描くコメントを現在の中心位置で画面全体を埋めるまで拡大する。横画面の下スワイプはサイズを維持して下へ移動する。操作UIを隠し、下の情報パネルは実際の回転まで動かさない。見た目の到達位置で指を離す前に切り替える。詳細は `comment-motion-swipe-navigation.md` を参照する。
4. 一時的な上流HTTPの切断・タイムアウト・503等では、VLCへのローカル接続と保存済みデータを維持して、失敗した同じバイト範囲を最大二回再取得する。前景復帰でも上流HTTPの接続プールだけを更新し、保留中の再試行を進める。成功時は通信警告を解除する。認証失敗・ファイル変更・不正なRange応答は既存ストリームへ混ぜず、再試行の期限・回数を超えた場合だけ従来の現在位置からの復旧へ渡す。

## 映像資源が中断された後の復帰

AVFoundationの `requiresFlushToResumeDecoding` または `AVErrorOperationInterrupted` を検出した出力は、その記録をレイヤーのflush後も保持する。flushは表示面のエラーを解除するが、VLCの映像復号経路が正常に戻ったことを保証しない。

前景復帰では、該当出力を使う映像トラックを解除し、選択解除と古い出力の除去を確認してから同じトラックを選び直す。従来の200ms固定待ちは使用しない。同じ入力を一時停止したまま現在位置へシークし、キーフレームを新しい復号器へ供給する。新しい出力と映像サンプル、シーク完了を確認してから最新の再生・停止指示を適用する。入力、HTTPのローカル接続、音声トラック、保存キャッシュは維持し、ファイル先頭の再生は行わない。

選択解除・再選択には4秒、フレーム準備には10秒の期限を設け、完了しない場合だけ現在位置から入力を開き直す。準備中の再生・停止指示は最後の希望を保持し、ユーザーのシークは準備後に適用する。途中でバックグラウンドへ戻った場合は復旧作業を止め、次の復帰で続ける。プレイヤー終了や入力の再生成では旧作業を無効にする。PiPが稼働中の映像はこの前景復旧で中断しない。

シミュレーターでは出力の中断状態を注入し、実際のVLC映像トラック解除・出力再生成・停止位置での準備・再生再開を試験する。これは実機のVideoToolbox資源失効そのものを再現した試験ではない。

## 診断の読み方

### 復旧用シーク後に入力が停止した場合

映像だけの再準備中にVLCがStopped／Errorになった場合は、シーク完了通知とは別に失敗を検出し、ユーザーの再生操作を待たず保存位置から入力を再生成する。復旧用シークはバックグラウンドの保存位置を無効化しない。通常の接続切り替えだけでは入力を再生成しない。

入力再生成へ移る際には映像だけの作業とその表示フラグを解除する。再生成後も新しい出力の現在に近い映像を確認するまで復旧中として扱い、一時停止時は保存位置の映像、再生時は異なる画素の到着を確認する。入力の準備には25秒、準備後の映像確認には最低8秒の期限を設ける。自動の入力再生成は一回に制限し、失敗時は読み込み表示を解除して再読み込み操作を表示する。ユーザーの明示的な再読み込みと新しい復帰は新しい試行として扱う。

`video.resumeFallback` は理由（0期限、1停止、2エラー、3シーク失敗、4出力監視からの移行）、保存位置、再生希望を記録する。`video.reloadConfirmed` は再生成後の映像確認、`video.resumeFailed` は回復不能を記録する。

`range.connectionEnd` はローカル接続の終了を区別する（state: 1キャンセル、2失敗、3ヘッダー送信エラー、4本文送信エラー）。errorDomainは0なし、1POSIX、2DNS、3TLS、4その他で、コードは数値のみ。接続の終了そのものは再読み込みのトリガーにしない。`vlc.inputWarning` は警告／エラーを固定分類（kind: 0その他、1シーク、2EOF、3読み取り、4接続、5復号、6demux）と件数で保存し、本文は保存しない。

`vlc.inputEOF` はVLC入力ループの固定メッセージに対応する。警告を伴わない入力終端も記録し、録画の自然終了位置や読み取り接続終了との前後関係を確認できるようにする。

シミュレーターでは復旧用シーク直後に実際のVLC入力を停止させ、自動の入力再生成・再生／一時停止希望の維持・位置の維持・読み込み表示の解除を確認する。期限切れでも表示を解除し、再生成を繰り返さないことを試験する。これはVLCが実機で最初に停止する原因を確定する試験ではない。

- `player.sample` の `decodedVideo` / `decodedAudio` / `displayedPictures` / `lostPictures` はVLCの累積値。差分と入力の再生成を併せて見る。
  この統計は入力ループから公開されるスナップショットで、映像の描画ごとに更新されるものではない。統計が短時間変わらないことだけで映像停止と判断せず、画素変化と表示予定時刻も確認する。
- 既存の `decodeAge` は互換性のため残すが、実際には映像出力へのサンプル到着からの時間。同じ画像の再出力も含む。明示的な別名 `outputArrivalAge` を追加した。
- `video.outputChanged` と `video.sample.outputID` は出力再生成を識別する。`monitoring` は画素の観測が有効な状態、`changes` は観測した画像の変化数。画像本体は保存しない。
- `video.sample.resourceInterrupted` はflush後も保持する資源中断の記録。`video.resumeRebuild`、`video.resumeOutputRetired`、`video.resumePrepared` で同じ入力の映像処理を作り直した流れを追う。`video.resumePrepared` は停止位置のフレーム準備完了であり、連続再生の確認とは区別する。`video.resumeTimeout` と `input.reloadRequested` は入力再生成への移行を記録する。
- `video.repair` / `video.recoveryConfirmed` / `video.recoveryFailed` は復旧命令と実際の画像更新の確認を分ける。`video.trackRestored` 自体は成功確認ではない。
- `range.retry` / `range.retrySucceeded` / `range.retryFailed` は再取得した範囲・回数・経過時間・HTTPと通信エラーの数値を記録する。接続先、認証、番組名、コメント本文は含めない。

## 検証

ネイティブ試験で、同じ画像の再出力・出力再生成・未来の表示時刻・実際の画像更新・停止中の期限・復旧回数の上限を検証する。
シミュレーターで、新しい出力の観測と画像変化、下パネルが動かないスワイプ、実際のローカルRange接続を保った上流の二回の切断と503からの復旧、ファイル変更の拒否、終了時の再試行キャンセル、前景復帰による再試行の重複防止を確認する。
中断資源の復帰試験にはフレームごとに色が変わる合成MP4を使用する。同じ入力・中断位置の維持、新しい出力でのフレーム準備、再開後の時刻進行・継続する画素変化・現在に近い表示予定時刻を確認する。累積復号数は診断値として残し、即時の増加を成功条件にはしない。
実機のスリープ復帰で最初に映像が固まる原因と、その修正完了はこの自動試験だけでは確認できない。

試験中に、終了時のVLCKitログ解除が進行中のログ通知と相互待ちになることをスタックで確認した。空のプレイヤーオプションで使う共有ライブラリには、数値だけを記録する状態を持たないロガーを一度登録し、プレイヤーの終了・再起動ごとに解除・再登録しない。ログ本文を出力しない制限と件数上限は維持する。
操作UIの自動非表示確認は、同時刻に期限を迎えたメインキューとRunLoopタイマーの実行順を混同しないよう、確認も同じRunLoopへ登録する。2.5秒の動作仕様は変更しない。
