# 録画一覧のページ履歴と候補メニューからの戻り

Web参照は`RecordedPage.tsx`のページ変更・エンコード追加、`RecordedDetailPage.tsx`の単体追加、`RecordedBulkEncodeDialog.tsx`の一括成功通知、`EncodePage.tsx`の`LinearProgress`。ページ履歴の左右スワイプと全面の戻り判定はユーザー指定のアプリ独自仕様。

| 対象 | 実装・確認条件 |
| --- | --- |
| 履歴 | `NeoRecordedPageHistory`がページ番号・スクロール位置と現在位置を保持する。重い画面・画像は履歴に保存しない。通常のページ選択は読み込み成功後に訪問を追加し、戻った後の新規訪問では進む履歴を捨てる。同じページの更新は履歴を追加しない。 |
| 復元 | 一覧ルートでは右で戻る、左で進む。指に追従し、終了時に移動が確定した場合だけ読み込む。取り消しや取得失敗ではページ・カーソル・表示中データを維持する。復元位置は現在の一覧サイズに収まるよう補正する。 |
| 条件分離 | APIの同一性、ユーザー識別の世代、検索条件、並び順、ユーザー絞り込み、件数が変われば履歴を作り直す。タブからの先頭復帰・履歴タブからの位置指定は新しい起点になる。別タブの切替自体は訪問に追加しない。 |
| 優先順位 | 詳細・検索結果などのナビゲーションスタックを閉じる操作が先。一覧ルートではページ履歴、その次に既存の視聴履歴への戻りを使う。戻り先がなければメニュー。進む先がない左スワイプは消費しない。iPadの常設サイドバーは維持する。 |
| 候補 | `contentPan`をShellの共通祖先に置き、候補を覆うビューも対象にする。スワイプ開始で候補の表示だけを消し、指が離れるまでヒット判定のビューを残す。候補選択は抑止し、終了時に候補を片付ける。通常のタップ・縦スクロール・横専用部品・文字入力は競合させない。 |
| 通知 | 単体はWeb同様に件数なし、一括は成功総数付き。`NeoEncodePlan.successMessage`を使用する。 |
| 進捗 | 同じジョブの既知値の更新だけUIKitで補間する。初回・別ジョブ・未確定から確定への切替・再利用時は正しい位置を即時表示する。同じ値の再表示では進行中のアニメーションを作り直さない。位置・バッジは変更しない。 |

モデル検証は`tests/page-history/main.swift`、通知とAPIは`tests/encode/main.swift`、実画面の操作は`runRecordedHistorySmoke`と`NeoEncodeSmoke`。`player-feedback` / `encode`の同じiPhone/iPad実行にまとめる。API失敗の注入、キャンセル、復元、分岐、ユーザー・フィルター変更、実際のPLAY候補を表示した状態の戻り、単体/一括の実通知、進捗の更新/初回/再利用を対象とする。プレイヤー内部のジェスチャーや再生処理は変更しない。
