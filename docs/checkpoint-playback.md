# AetherEngineとAV1チェックポイントの再生試験

## 試験の範囲

設定→アプリ設定→再生エンジンで「試験用：Aether＋AV1チェックポイント」を選ぶ。
「チェックポイントを使用」のオン／オフを次の再生開始時に固定し、同じprivate dav1dで比較する。
対象は録画完了済み・1080p以下・YUV420の8/10bit AV1のエンコード済みPLAY。
通常のVLC、Aether比較、AVPlayer比較、TS、STREAMINGの経路は維持する。
既存の比較プレイヤーUI、音声同期、映像レンダラー、パケットキャッシュを使用する。
比較経路のコメント・字幕・PiP・履歴送信など従来未対応の機能は今回も有効化しない。

## 保持と作成

- 表示位置を基準に、過去最大60秒・未来最大20秒。
- 圧縮状態と管理情報の合計を128MiB以下に保ち、時間範囲外と容量超過の遠い地点を解放する。
  元の圧縮パケット、復号器、描画画像、1件の圧縮作業領域は別の量。
- 最初の間隔は約6秒。本物のキーフレームから2.5秒以内と既存点の近傍は避ける。
  実際の保存位置・保持数をログに残し、今後の間隔調整に使う。
- 再生用復号器は境界で出力を全て受け取り、参照を保持する軽いcaptureだけを行う。
  行差分・バイト整形とZstdレベル1は1つのutilityワーカーで処理し、保存の待ち行列は作らない。
- 先行復号器は1つ。同じ取得済みパケットの履歴をutility側で読む。新しい通信は発生させない。
  読み取りは最大32MiB・4096パケット・250msに制限し、復号は短いバーストで譲る。
  最新の保存点が十分先にある間は処理せず、再開時には利用できる保存状態から先行復号も再開する。
- メモリー警告では保存点を縮小し、先行処理を中断して15秒休止する。終了時は全作業を失効させる。

## シーク

Aetherの取得済みパケットにヒットしたシークだけで保存点を選ぶ。
目的位置より前、かつ最寄りの本物のキーフレームより後の保存点を使用する。
キャッシュの通常の先頭パケットから、保存時の最後のパケットの位置・PTS・DTS・サイズを照合し、
そのパケットまでは復号を省き、保存状態を復元した後に次のパケットから目的位置まで復号する。
保存境界で既に出力した全フレームより後の目的位置だけが候補となる。
音声・映像のスキップ閾値、シーク世代、時計の再設定は既存のホスト処理を使用する。
候補がなければ通常の同じdav1dによるシーク。復元・復号で異常を検出した場合は保存点の使用を
無効にして通常シークを1回行い、`checkpoint.fallback` を記録する。

## 分離と所有権

private dav1dのC APIはFFmpegの構造体を境界へ出さず、借用中のYUV画素だけを同期的に渡す。
既存のSoftwareVideoDecoderが、その借用画素を自身の表示バッファーへ変換する。
新しい状態転送APIは同じplayer sessionのcookieと同じ復号器設定を確認する。
既存の診断APIは保存元と異なる復号器を引き続き拒否する。
スレッド、mutex、ワーカーのスタック、DSPテーブルは保存しない。

## 検証とログ

PCの`tests/checkpoint-playback.c`で、作成元の復号器を閉じてから別の復号器へ復元する。
8bit・10bit合成素材と1080p実録画の各素材で3回復元し、それぞれ240フレームの全画素とPTSが
通常復号と一致した。異なるplayer sessionへの転送拒否も確認した。

Actionsの`checkpoint-player`は、配布アプリをシミュレーターでオン／オフ各1回再生する。
実際のシーク先の5画像を既存の正解画像と照合し、先読み側の保存・2回以上の実復元、
保持上限、時間範囲外の解放、メモリー警告での縮小、オフ時に保存しないことを確認する。
通常の全UI・通信障害マトリクスやGPU圧縮カーネル試験はこのscopeでは実行しない。
シミュレーター成功はiPhoneの性能・消費電力・発熱の保証ではない。

共有用の`playback-diagnostics.json`には以下を記録する。

- `checkpoint.configuration`: オン／オフ、60秒／20秒、128MiB。
- `checkpoint.cache`: 地点数、保持量、最古／最新位置、先行作成数、ヒット／ミス、プロセス使用量。
- `checkpoint.saved`: 再生側／先行側、保存位置、容量、圧縮時間。
- `checkpoint.seekPlan` / `checkpoint.restored`: 候補の有無、使用位置、実復元時間。
- `checkpoint.captureMiss` / `checkpoint.fallback`: 保存できない境界と異常時の代替処理。

既存の`seek.firstFrame`等の実映像確認と組み合わせ、復元時間だけをシーク時間として報告しない。

## ビルド281の確認結果

- アプリのソースは`c159b76e999c169b0c7f7c2945c1b07f07995581`。
  [Actions run 40479000073](https://github.com/nyanz00/NeoEPGStation-iOS/actions/runs/40479000073)の
  `checkpoint-player`が成功した。端末用・シミュレーター用のビルドと各146件のFFmpeg参照先検証が通った。
- オンでは実復元5回・先行側の作成を確認し、異常時の代替処理は発生しなかった。
  オフでは保存点を作成しなかった。オン／オフ各5枚のシーク先画像が正解画像と一致した。
- 保持上限、時間範囲外の解放、メモリー警告時の縮小も確認した。
  シミュレーターでの復号準備時間は実機の表示遅延として扱わない。
- 配布ファイルは`NeoEPGStation-build281.ipa`、SHA-256は
  `27a21160ed9a66caacb1c945a0bc04067901b4699e1535a02c21f6e9eb1de137`。
  ZIPの整合性、ビルド番号、同梱した変更ソース・パッチと当該コミットの一致を確認した。

実機では同じAV1録画を同じ位置でオン／オフ比較し、通常の再生診断ログを取得する。
速度だけでなく、保存地点数・先行作成数・保持量・圧縮時間・プロセス使用量と、再生中の発熱も確認する。
