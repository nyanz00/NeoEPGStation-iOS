# PLAYのシーク診断とコメント・PiP改善

## 今回の範囲

- シーク先・VLCの完了通知・20秒期限・入力再起動・映像更新再開を同じシーク番号で記録する。
- Range要求、1MiBブロックのヒット／不足、上流要求の応答時間、保持範囲の破棄を記録する。
- シーク処理とキャッシュ保持方針そのものは変更しない。実ファイルで遅延原因を確定するための診断を先に追加した。
- コメント時計は、再生意図とバッファリング状態に加えて、VLCの映像出力から受け取った表示予定時刻を確認する。
  250ms以上表示予定フレームの更新が途切れたら描画時刻を保持し、VLC時刻だけが進んでもコメントを進めない。
  シークでは明示的に時計をリセットし、復帰時は現在の再生時刻へ合わせ直す。
  出力フレームの更新を使う判定であり、液晶画面への実表示完了を測るものではない。
- PiPはVideoToolboxで出力サイズに直接色変換・縮小する。CGImageは画素バッファを保持し、解放まで読み取りロックを維持する。
  全解像度のDataコピーを除去する。PiP中は通常画面のMetalコメント描画を停止する。
- PiP出力上限を1280×720に変更し、大きいコメントは表示倍率に合わせた解像度で文字画像を用意する。
  コメント速度5.25秒と60Hzの描画目標は維持する。実機での性能向上率は未測定。
- シークバーのドラッグ中と完了待ちでは移動先時刻を表示する。実シークは指を離してから行い、完了・失敗・取消で実時刻へ戻す。
- バッファリング表示は専用の表示状態で管理し、診断用ラベルへの別の通知で消えないようにする。進捗更新は数字のみを変更する。

## 実機ログの取り方

1. 対象のエンコード済みPLAYで通常再生する。
2. 10秒巻き戻しやシークバー移動を行い、再開まで待つ。
3. プレイヤー設定の「全般」から「再生診断ログを共有」を押す。
4. `playback-diagnostics.json` をファイルへ保存して確認する。

ログはメモリ内4096件まで、新しいプレイヤー開始時にリセットする。自動送信しない。
共有時だけ一時ファイルへ保存し、次の共有では同じファイルを置き換える。
URL、接続先、認証情報、番組名、コメント本文は出力しない。
`originSeek` と要求番号は、前のシークで開始し次のシークで完了した通信を区別する。
`cache.hit` は保存済みブロックを読み出したことを表す。キャッシュ全体がシーク先を完全にカバーする保証ではない。
`player.sample` はVLC時刻・映像フレーム更新の間隔・バッファ状態を1秒ごとに記録する。
`pip.sample` は合成回数・平均合成時間・解像度・コメント時刻を記録する。

## 検証

ActionsでSwiftテスト、型検査、デバイス／シミュレーターReleaseビルド、既存の合成動画・PiP・UIスモークを実行する。
追加検証は、映像停止中にVLC時刻だけ10秒以上進む時計、将来フレーム、復帰とシークリセット、
縮小変換とCGImage保持中のバッファ再利用、ドラッグ時刻・残り時刻・完了待ち・取消、
1〜3％の進捗に他の状態通知が割り込む表示、JSON共有を対象とする。
実ファイルでの長い待ち時間の原因確定・弱い通信での同期・実機バックグラウンドPiPは、実機ログと視聴確認が必要。
