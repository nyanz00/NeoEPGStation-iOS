# 録画済み一覧の編集・一括操作

Web参照: `RecordedPage.tsx`、`recordedBulkDelete.ts`、`queries.ts`、`MulticastIcon.tsx`、`programDialogStyles.ts`、テーマ、API型定義と`RecordedApiModel`の一括変更/移動処理。サーバー変更・実データでの変更試験は行わない。

| Webの仕様 | アプリの対応 |
| --- | --- |
| メニューの編集から選択モードへ | カード押下は詳細を開かず選択を切り替える。チェック表示、選択件数・合計容量、全選択/解除、編集終了。選択は現在のページ内だけで、取得結果から消えたIDは除外する。 |
| 編集中の表示分岐 | 通常のユーザー選択・検索・メニューとページ移動を隠す。600px未満は全選択→一括操作→削除→終了、以上は全選択→エンコード→ユーザー→移動→削除→終了。Webと同じMUI/MDIのパスを使用する。 |
| モバイルの一括操作ダイアログ | エンコード、ユーザー変更、サブディレクトリ移動の順。削除はヘッダーに独立して表示。 |
| 一括ユーザー変更 | 通常ユーザーだけを選択し、WebのUserSelectorと同じく現在の通常ユーザー、存在しなければ最初の通常ユーザーを初期選択する。`PUT /recorded/bulk/user`へ録画ID群と変更先を送信。成功後は編集を終了して現在の絞り込みで再取得する。アクティブユーザーは変更しない。 |
| サブディレクトリ移動 | `GET /recorded/directories`で候補を取得し、既存名/新規名/空欄のルート直下に対応。`PUT /recorded/bulk/subDirectory`で全動画ファイルをサーバー側で移動。エンコード中は操作を無効化し、録画中・衝突・パス検査はサーバーの拒否を表示する。 |
| 一括削除 | 初期値すべて。全体、オリジナルのみ、エンコード済みのみ、ファイル名指定。全体は録画削除、その他は該当する動画IDを削除する。対象なしでは実行不可。部分失敗は失敗した録画だけ選択を残す。 |
| 完了・失敗時の再表示 | 選択と認証を処理開始時に固定し、受理済みの変更を自動再送しない。録画キャッシュを無効化し、一覧・詳細・履歴へ変更通知する。一括処理中の一覧再取得は完了/ダイアログ終了までまとめる。 |

削除は1録画内のファイルを順番に処理し、録画間は最大4件を並行処理する。これはWebの無制限並行取得をネイティブ側で制限した差異。録画中の動画削除が録画全体の削除になるサーバー仕様では、その録画の残りの動画IDを送信しない。

一括エンコードは意図的に入口と空のダイアログだけを用意し、APIへ接続しない。クリーンアップ・アップロードは今回の対象外。

録画検索のキーワード欄は検索キーを指定し、Returnで最新の文字列を既存の検索処理へ渡す。日本語入力の未確定文字がある間は送信しない。候補取得で欄を再利用してもReturnの処理を重複登録しない。

検証は`player-feedback` / `recorded-bulk`に限定する。Foundationの対象生成・部分失敗・認証中断・並列上限・API契約試験と、iPhone/iPadの選択・ダイアログ・模擬API・検索キーの試験を行う。ビルドと模擬試験の成功は、実機・実サーバーでの削除/移動成功とは区別する。
