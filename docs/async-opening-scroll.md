# スクロール回帰と遷移後の画面構築

## 対象と成功条件

- 一覧・履歴・設定一覧では、次に開く画面のUIViewControllerやUI部品を作らない。録画一覧の高速スクロール中に詳細画面の生成数と新規先読み要求が増えず、停止後にデータだけ取得することを確認する。
- タップ直後の軽いヘッダー・背景による150msスライドの最初の表示フレームを確認してから本文を構築する。本文はフレームを挟んで分割し、準備完了後に100msでフェード表示する。先に開き始めたことと、本文が使える状態になったことを別々に計測する。
- 戻る操作で構築をキャンセルする。古いタスクの終了で新しい構築の状態を上書きしない。
- drop・半角表記・Annictは、データだけの共有キャッシュと必要な取得を使い、本文を見せる前に反映する。取得失敗時のdropを0と偽らない。
- 同じユーザーの確認開始・完了でも、表示中の一覧を再取得する。各要求の終了処理は最新の要求だけへ適用し、途中破棄・中断で読み込み表示を残さない。非表示の一覧は更新が必要なことだけ記録し、表示時に取得する。
- 一時的なセッション確認エラーはユーザー選択・保存トークンを維持し、一覧・履歴を利用できる。認証が必要なAnnict等は確認完了まで許可しない。明確な401/403・invalid応答だけをセッション無効と扱う。ユーザーが実在しないことが確認された場合のmaster選択と、通信失敗を区別する。

## 原因

build338は、表示範囲の入れ替わりに伴って最大2件の詳細画面を繰り返しメインスレッドで生成していた。保持数の制限は作成回数の制限になっていなかった。タップ後の開始応答は測定したが、一覧操作への負荷を測定せず、実機でスクロール回帰が報告された。

録画一覧は、認証世代変更後の応答を破棄する処理に再取得・終了処理が伴っていなかった。同じユーザーの復元では再取得されず、コレクションを透明にしたままスピナーが残る経路があった。

## 実装と検証

先読みはスクロール停止後250ms待ち、表示範囲16件まで、1ワーカー・同時最大2要求とする。途中の画面生成コールバックは廃止する。実行済みのHTTP応答は共有データとして完了してよいが、スクロール中に後続要求を追加しない。

設定の本文は約3msの作業ごとに表示フレームへ処理を返す。詳細はサムネ・メタデータ・操作欄・本文をフレームごとに構築する。UIの生成自体はメインスレッドで行うため、重い処理を一度に実行しない。

HTTPスタブで同一ユーザーのセッション確認500、明確な401、再試行成功を注入する。保存トークンの維持、読み込み終了、履歴閲覧、保護機能の停止を照合する。UIKitのアニメーション付き一覧スクロール中と静止中のフレーム間隔を記録し、実際の移動、新規取得停止、詳細画面生成ゼロ、停止後のデータ取得を検証する。これは実機での物理タッチ/FPS測定とは区別する。

両SDKのビルドと対象の表示・ナビゲーション試験を実行する。再生処理は変更しないため、再生全体試験は追加しない。100msの開始応答目標を未達でも成功に変更しない。測定コールバックの同一フレーム内の順序差には1msだけ許容し、構築開始が移動フレームより先行していないことを確認する。

build340では、試験がモーダルのdismiss完了前にpushし、UIKitがnavigation stackの変更を拒否した。履歴の表示とスクロール停止後の先読みを確認する画面が実際には開かれていなかったため、この2項目は未確認とする。次の試験ではdismiss完了を待ち、対象画面がnavigationの先頭かつwindow内に存在することも検証する。

build341では初回起動のdidBecomeActiveがスタブAPI設置後に届き、試験用認証を実機用の復元処理で上書きする競合が現れた。シミュレーターのsmoke実行中だけ自動復元を除外し、認証試験から明示的にrestoreする。また、試験終了後もshellが使うURLSessionを無効化していたため、最終一覧取得で例外が発生した。各試験を独立プロセスで起動する前提で、スタブセッションはそのプロセス終了まで維持する。通常起動・実機の復元処理は変更しない。

## build342の結果

アプリソースは`e294a0f`、[実行42232759285](https://github.com/nyanz00/NeoEPGStation-iOS/actions/runs/42232759285)。実機・シミュレーター両SDKのビルド、モデル31項目、対象機能75項目はiPhone/iPadとも通過した。起動時の認証維持、表示中の履歴・一覧を実際に使った認証確認500/401/再試行、スクロール停止後のデータ取得、構築キャンセルも含む。対象試験のstderrは両端末とも空で、終了後のセッション例外は発生しなかった。

| 初回のスライド開始（全般・視聴・詳細） | 96.0 / 16.8 / 17.0ms | 74.6 / 21.2 / 19.8ms |
| 再表示のスライド開始（同順） | 28.3 / 23.5 / 29.8ms | 22.3 / 13.6 / 47.9ms |
| 初回の本文構築完了（同順） | 145.8 / 290.2 / 385.6ms | 117.9 / 535.2 / 406.9ms |

本文完了は100msのフェードが始まる時点であり、フェード完了や実機タッチ応答ではない。上記はHTTP遅延を注入した単回のシミュレーター測定で、常に100ms以内という保証ではない。

スクロール試験では新規詳細要求・詳細画面の生成がともにゼロで、停止後にデータ取得だけが始まった。フレーム間隔の中央値は16.69 / 16.80ms、最大値は80.16 / 95.63ms。測定開始後に60件の試験用一覧の再配置も行っているため、これを実機の連続スクロールFPSや無停止の保証として扱わない。

iPhoneのナビゲーション47項目は通過。iPadは初回の47項目中、スワイプ開始40ms後の一時点の描画位置判定だけ未通過だった。受付・継続追従・戻る完了は通っていた。[同一アプリのiPad単独実行42247979280](https://github.com/nyanz00/NeoEPGStation-iOS/actions/runs/42247979280)では47項目すべて通過した。アプリ再ビルド・判定条件の緩和は行っていない。単独で再現しなかったことだけを記録し、負荷が原因だったと断定しない。

途中の再検証42238790382は、最初の試行がGitHubのmacOS ARMランナー容量不足で未起動、次の試行は新規起動したiPadへの不要なアプリ終了命令がタイムアウトし、試験未実施だった。次回は新規起動端末だけ終了命令を省き、アプリのソース・バイナリを変更せずに検証した。

最終照合では、対象機能75項目・ナビゲーション47項目が両端末とも通過。ソース、再利用アプリの同一性、実機用IPAのビルド番号342とSHA-256を照合した。IPAは`NeoEPGStation-build342.ipa`、SHA-256は`8ace14c95b2bb2499236665564cf0b4f94f75cb5c3a5e53f4ea5df7be39e4f83`。
