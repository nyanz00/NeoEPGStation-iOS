# TS実況ログ・ARIB表示時間・ピンチの表示と触覚

## ピンチ

1〜8倍の範囲と、映像だけを拡大する仕組みは維持する。
倍率は15ptの文字幅に10ptの余白を加えた円（最低32pt）、「元のサイズ」は左右10pt・上下6ptの余白を持つ角丸5ptの矩形にする。
1倍の縮小操作でも「元のサイズ」を表示し、指を離した後の0.8秒で消す。

Core Haptics対応端末では拡大開始に弱い衝撃と28msの小さな減衰、1倍への復帰・1倍での縮小操作には強めの衝撃と55msの減衰を出す。
拡大開始・元のサイズの境界はそれぞれ1ジェスチャーにつき1回。指を離すだけでは触覚を出さない。
音声イベントを含まない触覚専用エンジンを使い、非対応・再生失敗時はUIKitの弱い／中程度の触覚へフォールバックする。
シミュレーターでは倍率・表示形状・発火条件を確認し、触覚の感触そのものは実機確認と区別する。

## TSの実況過去ログ

録画ファイルの型をプレイヤーへ渡し、TSは `/api/videos/{videoFileId}/comments` を使う。
サーバーの `VideoCommentApiModel` とWebの `RecordedJikkyoCommentCore` に合わせて、`source=jikkyo`、`timeBase=video` のJSONを読み取る。
ASS字幕の探索・抽出へは回さない。エンコード済みの実況ASS読み込みは従来のままとする。

本文はASSタグとして解釈せず、そのまま表示する。色はサーバーが解決済みのRGBを使い、大／中／小と流れる／上固定／下固定を既存のコメント形式へ変換する。
流れるコメントは5.25秒、固定は既存の4.5秒を使う。重なり回避、サイズ・不透明度、シーク後の配置、終端補正、PiP合成は同じタイムラインを使う。
通常のARIB字幕選択は実況ログの選択と独立して維持する。

取得APIは全編を返すため、JSONはプレイヤー内で一度だけ取得・解析して保持する。最初に再生位置の30秒前から210秒の配置・文字画像を準備し、既存の全編切り替え処理へ渡す。
元の動画内秒数を使い、途中開始時に開始位置を二重加算しない。リダイレクトは同一オリジン・同一動画のコメントAPIに限定する。
ログなし・取得失敗時はコメント欄へ状態を表示し、動画再生を止めない。準備待ち設定の15秒上限も適用する。

## ARIBの再現条件

`tests/fixtures/arib_timing.py` は架空の英字字幕と表示・待機・消去命令を、合成映像・音声のTSへ多重化する。実放送の録画は含まない。

|動画内秒|命令|Web aribb24.js 1.11.5の保持|
|---:|---|---|
|1|FIRST表示|次の字幕（5秒）まで|
|5|SECOND表示、1秒の待機のみ|次の字幕（9秒）まで|
|9|THIRD表示、2秒待機後に消去|11秒まで|
|13|LAST表示|消去（16秒）まで|
|16|消去のみ|非表示|

WebのCanvasProviderへ同じPESを渡し、文字描画だけを置き換えてパーサーの終了時刻を確認する。
ネイティブ側は同じTSを固定版VLCKitで再生し、字幕出力ビューの領域数と画面画像を2・4・6.5・8・10・12・14・17秒に保存する。
初回のビルド187では、FIRSTが2秒には存在して4秒には消えた。待機命令だけのSECONDも6.5秒・8秒には消え、Webの保持と一致しなかった。
固定版VLCのARIB復号器は無期限字幕の終了を開始時刻と同じ値にし、無期限フラグを付ける。字幕の選別側にはその終了値を有効と判断して期限切れにする経路がある。

補正は元データから表示・待機・消去の時刻だけを取り出し、VLCが描いた字幕画像を本来の保持区間だけ維持する。新しい字幕の描画と、明示的な消去は維持する。
データは既存Range応答から読むため動画の追加取得はない。字幕の字形・色・DRCSはVLCに任せ、実況コメント・通常ASS・字幕オフには適用しない。
VLCKit 4.0.0a25の字幕ビューとの接続に限定する。VLCが後から領域配列や不透明度を書き換えるため、保持時には位置・不透明度の値と不変のCGImage参照を保存する。画素データは複製しない。通常ASSは元の表示処理へそのまま渡す。
保持中の画像を監視する20Hzの処理は時刻と状態だけを確認し、毎回の画像生成・コピーはしない。消去時刻に達したら停止する。シーク・入力変更・字幕の解除・プレイヤー終了では保持画像を捨てる。

観測コードはシミュレーター限定。修正後の `arib-timing-smoke.json` は観測完了と `matchesWebTiming` の両方を成功条件とする。
通常ASSのフォント・黒帯などをWebへ合わせる変更は対象外。

ビルド189ではARIB比較・iPhoneとiPad UIが成功し、低速通信の観測終了時の復旧確認が失敗した。ビルド190では通信試験は成功したが、ARIBの最初の画像欠落が再現し、従来の初期途中開始試験も描画変化数が不足した。初期映像の試験は同じ描画変化条件を最大3秒まで観測し、ビルド191で通過した。

ビルド191で字幕生成地点を記録すると、最初の字幕は画像生成自体がなく、以降の3字幕だけが生成されていた。描画後の保持処理では補えないため、比較試験が再生途中で字幕トラックを選び直す操作を除き、既知のトラックを再生前のメディアオプションで選択する。字幕生成側への追加フックは撤去し、表示画像の保持に限定する。比較は同じアプリで3回行い、全回の画像・観測値を保存し、全回が合格した場合だけ成功とする。
