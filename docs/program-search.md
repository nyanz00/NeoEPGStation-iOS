# 番組検索

対象はサイドメニューの「検索」と、録画の「rule」から開くルール編集。

| 確認箇所 | Web の根拠 | iOS での対応と確認 |
| --- | --- | --- |
| 条件入力・クリア | `SearchPage`, `ChannelSelector`, `DateInput`, `core/search/options.ts` | キーワード・除外と各検索対象、放送局・放送波、ジャンル、曜日・時間帯・期間・番組の長さ、無料放送。放送波は局一覧とサーバー設定を照合。入力が不正なら送信せず、クリアで初期値へ。 |
| 検索と予約状態 | `SearchPage`, `GuidePage.reserveIndex`, `core/api/queries.ts` | `POST /schedules/search` と結果全体の期間を使った `GET /reserves/lists`。0件なら後者は呼ばない。取得失敗は原因ごとに再試行でき、予約情報の失敗を未予約として表示しない。半角表示・検索最大表示件数を適用。 |
| 結果・詳細と関連検索 | `SearchPage`, `GuideProgramDialog`, `ProgramBroadcastDetails`, `core/program.ts` | 件数、放送日時、局名、説明、状態チップと枠。番組詳細ではロゴ、番組概要と詳細、ジャンル・映像・音声、予約ユーザーを表示。関連検索から戻ると条件と位置を保持して再取得する。メニューから「検索」を選び直すと初期化。 |
| ルール作成・編集 | `SearchPage`, `RuleEditorDialog`, `RecordedItemActions`, `core/search/options.ts` | 検索の実行前にも「ルール作成」を開ける。録画の「rule」から既存条件を復元して再検索する。時刻指定のルールは放送枠と `GET /reserves?type=all&ruleId=…` の予約を表示する。 |
| ルール設定の保存 | `RuleEditorDialog`, `core/storage/settings.ts`, `rules` API | 「録画・保存」「エンコード」の設定を `POST /rules`、`PUT /rules/{id}` で保存。深夜をまたぐ時刻指定や、3件までの局別エンコードに対応。保存失敗時は入力を保持し、再試行できる。重複回避・エンコードなどの初期値は Web の既定値を使用する。 |
| 設定 | `SettingsPage`, `core/storage/settings.ts` | 「表示」で検索最大表示件数（初期300件）、放送詳細の初期展開、関連検索時の放送局・ジャンル指定を設定。接続先ごとに端末に保存。 |

検索条件は画面や結果の状態から分離して、ルール API の `searchOption` と同じ形にする。放送局・ジャンル・時間帯の候補は入力欄に沿って開く。放送局の候補はキーボードを閉じた後も選べる。キーワードと除外キーワードはそれぞれ右端の「×」でクリアできる。`DateTimePickerDialog` に合わせて日時選択を中央に表示する。日付は月間カレンダー、時刻は24時間のホイール式。テーマは既存のターコイズ・ダーク。関連検索の戻り履歴はアプリの画面スタックで保つ。

番組ダイアログは開いた時点で放送日時を表示し、放送情報の展開時は外枠の高さを保つ。未予約の番組には Web の予約設定欄とボタンの配置を再現する。予約設定欄と「詳細」「予約」は表示のみ。

値の選択欄は Web の `Select`、`ChannelSelector`、`RuleEncodeChannelSelector` を参照し、iOS では `NeoDropdownList` の `UITableView` を共用する。候補はキーボードと画面内の空きに応じて欄の上下に表示する。候補だけを開くときに0.12秒、閉じるときに0.08秒でフェードし、放送局とジャンルの複数選択や入力による絞り込みを開いたまま反映する。

検索条件とルール設定の入力欄・選択欄は、Web の `SearchPage`、`RuleEditorDialog` と MUI `InputLabel` に合わせる。空かつ未フォーカスでは欄内に表示し、フォーカス中または値があるときは枠線上に表示する。ジャンルと時刻指定ルールの開始・終了時刻は最初から枠線上とする。位置が変わるときはラベルを0.2秒で移動・拡縮し、枠線上で75%の大きさにする。「視差効果を減らす」がオンのときは即時に切り替える。

`SearchPage.handleRuleSaved` に合わせ、保存成功後は検索を開く直前の画面へ戻る。サイドメニューから検索を開いた場合は直前のタブを使い、ルール一覧からの作成・編集や関連検索では画面スタックの直前へ戻る。戻り先のない新規作成では検索を初期化する。

検証は `ios.yml` の `check_scope=player-feedback`, `ui_stage=program-search`。Swift モデル試験で検索・ルール保存の送信条件と予約状態の優先順を確認し、架空データとエラー応答を使って iPhone・iPad シミュレーターで検索、放送局選択、番組詳細、関連検索、ルール作成・編集、保存の再試行と戻る操作を確認する。

## ルール一覧

| Web の根拠 | iOS での対応と確認 |
| --- | --- |
| `RulesPage`、`UserSelector`、`VueCompatiblePagination` | 同じ条件で通常ルールを取得。ユーザー・キーワード・予約有で絞り込み、条件変更時は1ページ目へ。iPhoneのユーザー欄はヘッダーに収まる幅で最大112pt。閉じた欄は `master`、候補は `master（すべて）` と表示。表示件数は初期24件。「表示」のページ番号設定を使い、狭い幅では録画済みと共通のページバーを使用。取得中、空、取得失敗を表示し、更新失敗時は最後の一覧を保持。 |
| `RulesPage` のカードと操作、`rules` API | 有効状態・予約数・Annict・条件・エンコード内容を表示。スイッチで有効・無効を切り替え、三点メニューから関連録画・編集・削除。追加は検索画面を開き、一括削除で失敗したルールだけ選択を保持。Annict の無効化設定、関連付け解除の警告も反映。 |
| `SocketBridge` の `updateStatus` | 表示中だけ同じ通知で静かに再取得。API の変更・削除結果は認証状態を照合し、関連画面へ反映。 |

同じ `program-search` 検証で、ラベルの移動・縮小と入力状態、ルール一覧のフィルター、ページ切替、切替 API、一括削除の部分失敗、作成後の一覧復帰を架空データで確認する。視聴開始ダイアログではカード外に出た画質候補にヒットした後、画質だけが変わってダイアログが残ることを確認する。
