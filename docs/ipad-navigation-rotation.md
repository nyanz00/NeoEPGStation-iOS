# iPadのナビゲーション・プレイヤー回転

接続前はサイドメニューを表示せず、その幅も確保しない。接続フォームは全コンテンツ幅の中央へ配置する。
iPadの通常ページは全方向へ対応し、iPhoneの通常ページの縦固定を適用しない。

iPadの常設メニューは本文領域の幅・位置と連動して0.22秒で開閉する。閉じた後は通常の上40％の右スワイプで再表示でき、下60％の詳細への戻り操作は維持する。
メニュー内の左スワイプでも閉じられ、途中キャンセルは元の状態へ戻る。指の移動中は幅と位置を追従させる。

録画一覧のユーザー選択欄はWebのPageHeader/UserSelectorを参照し、上部バーの検索ボタンの前へ配置する。
幅160、高さ40、枠の角丸4、白0.23の線、12ptの浮いたラベル、16ptの白い選択名と24ptの下向き矢印を使用する。
選択メニューはUIKit標準のまま、実際の選択ボタンの位置・矩形をアンカーにする。本文に独立した行は確保しない。

## 回転

まずOSのscene回転要求を使用する。iPadは全方向をサポートし、通常ページや終了時にiPhone用の縦固定を要求しない。
要求のマスク、実際の対応方向、scene方向、ウィンドウ寸法、OSメジャー番号を診断へ記録する。
拒否された場合はエラーのドメイン・番号と固定カテゴリの理由を追加する。OSの応答本文はウィンドウ名などを含む可能性があるため保存しない。

iPadでOSが拒否する場合、または回転要求を適用せずウィンドウの向きが変わらない場合は、アプリが所有するプレイヤー表示面の回転で横／縦を切り替える。
映像と操作UIを一緒に回転し、セーフエリアも対応する軸へ換算する。VLCの入力・時刻・音声は維持する。
端末の物理的な向きが変わった場合もウィンドウ寸法へ再適応し、自動設定へ戻すと内部の回転指定を解除する。
これはOSが管理するウィンドウ全体を強制回転する処理とは異なる。マルチタスクを無効にする設定は追加しない。

回転失敗の画面通知は再生状態と別管理にし、2.5秒で自動解除する。一時停止や別の状態通知を解除の条件にしない。

## 検証

Actionsのcheck_ipadで、実際のReleaseアプリをiPadシミュレーターに導入する。
接続画面の縦横寸法での余白、メニューの途中フレーム・指追従・閉じた後のスワイプ・戻り領域、ヘッダー内の選択欄を確認する。
合成TSを再生し、回転ボタン・下スワイプ・上スワイプ、OS拒否時の内部回転経路、自動設定、再生継続、通知の期限を試験する。
scene回転結果はipad-orientation-diagnostics.jsonへ保存する。LiveContainerや実機固有の表示制約の再現とは区別する。
