# コメント開始準備・終端表示・映像復帰・読み込み表示

## 動作

- 通常の再生開始はコメントのシーク開始・終了処理を通らない。シーク後の非同期準備は実際のシーク世代だけに反映する。
- コメントは再生開始位置の30秒前から210秒分を先に取得する。Webの `RecordedWatchPage.tsx` の範囲と同じ。先頭からの場合は0〜210秒。
- コメント準備待ち設定は維持し、部分取得の解析・配置・開始位置の文字画像が準備できたら再生する。空の部分範囲は正常として扱う。取得失敗・無効化・15秒の期限は開始を妨げない。
- 全編は部分準備後に取得する。同じコメントの元時刻・本文・スタイル等と重複順序で識別を引き継ぐ。時計・文字画像キャッシュをリセットせず、表示中のコメントの行と動きの時刻を固定して全編を配置する。PiPも同一トラックの全編追加では描画キャッシュを破棄しない。
- 全編の識別照合・終端補正・時刻索引は別の待ち列で計算し、準備中にトラックや表示条件が変わった結果は反映しない。コメント一覧の行は一覧を開いたときだけ作る。
- 全編取得失敗時は用意済みの部分範囲を維持し、範囲外へのシーク・範囲終端への接近で新しい部分範囲を取得できる。
- 終端付近の流れるコメントは実際の文字幅と5.25秒の移動時間から出現時刻を前倒しする。元の投稿時刻による通常コメントの順序と移動速度を維持し、重なり回避は補正した時間で行う。
- 初期準備、シーク、再接続、映像復旧とバッファリングを中央のスピナーとその下の文言へ集約する。バッファリング中は数字のみ更新し、他の診断文言に上書きされない。通常の操作UIを隠しても案内を表示し、中央を押した再生／停止の指示は最後の希望として受け付ける。左上の案内は表示しない。
- 復帰時には映像表示待ちのキューを整理する。表示中の停止画像とVLC入力は保持する。復帰後だけ低頻度の画素サンプルと表示時刻・レイヤー状態を監視し、同じ画像の再出力を正常な映像更新と見なさない。
- 時刻が進む一方で映像が変わらず、停止時の更新頻度または表示待ちの異常が続いた場合、まず表示キューを整理し、その後も続く場合は選択中の映像トラックだけを再選択する。入力・音声・キャッシュを停止せず、先頭へのシークも行わない。修復回数は復帰ごとに制限する。静止画の一致だけでは修復しない。

## 診断と確認

部分／全編の取得時間と解析時間、配置計算時間、部分の文字画像準備、全編切り替え、描画更新の遅れ、映像表示面の状態と復旧段階を数値で記録する。認証・接続先・コメント本文は記録しない。

ネイティブ試験では範囲指定、重複を含む識別維持、表示中の行の維持、終端コメントの全体進入と速度維持を確認する。シミュレーターでは既存の再生・シーク・復帰試験に加え、初回にシーク終了処理が走らないこと、全編追加で時計を戻さないこと、中央案内が操作UIの表示状態から独立することを確認する。

実際のiPhoneのロックで発生する映像停止と実サーバーの抽出時間は、シミュレーターだけでは検証できない。実機結果はビルド・自動試験と区別する。
