# 録画中

Web 1.1.0 の `client/src/pages/RecordingPage.tsx`、`client/src/components/RecordedItemActions.tsx`、`AppLayout.tsx` と `SocketBridge` に対応する。

- 一覧は `GET /api/recording` を使う。番組名、放送局、放送時間、概要、サムネイル、録画中バッジを表示する。カードを開くと録画詳細に進む。初回取得中、空、取得エラーを表示する。表示件数はサーバーごとに端末へ保存し、初期値24、範囲1〜1000とする。
- 録画中一覧で番組がある間は `GET /api/recording/dropStatus` を初回と5秒間隔で取得する。別画面とバックグラウンドで停止する。カウンターの更新では行の高さを変えない。一覧本体に変更があれば、ドラッグと減速が終わってから反映する。
- メイン画面のサイドメニューは `GET /api/recording?limit=1` の総件数で録画中のアイコンを切り替える。サーバーの `updateStatus` を受けて再取得し、専用の定期ポーリングは行わない。
- 停止は `POST /api/recording/{id}/stop`。サーバーが予約を取り消し、途中までのファイルを録画済みに残す。録画中ファイルの削除は `DELETE /api/videos/{id}`。録画中はサーバーが録画全体の削除に切り替える。複数操作で一部が失敗した場合は失敗分を選択状態に残す。録画と予約の変更通知で関連画面を更新する。
- iOSでは詳細と操作メニューに既存のネイティブ画面を使う。カウンター欄の高さを先に確保し、件数が初めて表示された瞬間の行の移動を防ぐ。

検証は `ios.yml` の `recording-actions` を使う。架空データでページ送り、カウンター更新、アイコン、停止・削除の経路を確認する。
