# PLAYの通信待機・iPadの戻る・ピンチ拡大

## 通信待機

HTTPの遅い先読みだけでは停止しない。選択中の映像トラックがあり、実際の映像供給・表示が途切れ、上流のRange取得も未完了の場合に、ユーザーの再生希望を維持したままVLC共通の音声・映像時計を一時停止する。
新しい有効なデータが届いたら最後の再生希望に従って再開する。次の先読みがすでに始まっていても、到着済みデータの世代で再開可能と判定する。
バッファリング100％や一時停止画像の再出力だけでは映像の復帰完了にせず、新しい映像復号と新着映像を確認する。待機中もユーザーの再生・停止操作を受け付ける。
音声だけのバックグラウンド再生、明示的な一時停止、シーク、入力再読み込みは区別する。映像が低フレームレートの場合は待機判定の間隔を延ばす。

通常のヘルスチェックは既存のフレーム時刻・カウンターを0.5秒の更新処理で読む。キャッシュのディスクI/O待ち列と別の短いロックで通信待機状態を取得し、画像コピーや画素比較は追加しない。
映像復旧の監視は起動直後から行い、復帰後45秒で終わらせない。復号器修復時の画像変化確認は従来どおり期間を限定する。
必要な場合の出力修復・中断位置での入力復元は段階ごとに成功確認と期限を設け、失敗を無限ループにしない。
中央に通信待機・映像再開・映像復旧の状態を表示する。

診断には音声の出力数、映像の遅延・破棄、入力・demuxの読取量を追加する。VLCの警告は時計/PCR、遅延/破棄、VideoToolboxを固定カテゴリへ分類し、URLなどを含み得る生のメッセージを保存しない。

## iPadの戻る

iPadプレイヤーでは縦横とも、上30％の右スワイプはメニュー、下70％は詳細へ戻る。指への追従・確定・キャンセルは既存のプレイヤー終了トランジションを使う。
iPhoneは縦40／60、横はメニューのみの判定を維持する。
詳細から一覧への戻り操作では、ドラッグ開始時に所有者を決める。途中でナビゲーションのスタックが1枚になっても、履歴への戻りに切り替えない。

## ピンチ

映像領域の2本指操作で1〜8倍を連続的に指定する。VLCの外側の描画ビューだけを中央基準で拡大し、はみ出す部分は映像領域でクリップする。
操作UI・コメント・番組情報・PiP映像の倍率は変えず、入力・復号器・シーク位置・通信も変更しない。
映像領域の寸法変更時は、変形前の座標でVLCの枠を更新してから倍率を適用する。新しいVLC出力にも現在の倍率を適用する。再生を閉じると倍率は破棄する。

動画の上中央に半透明の円形表示を置き、操作中は「2.0×」など、1倍なら「元のサイズ」と表示する。指を離した後は0.8秒残して消す。
1倍から縮小しようとしても1倍を維持して「元のサイズ」を表示する。
拡大開始で弱い触覚、元のサイズへ戻った時・元のサイズで縮小しようとした時には強めの触覚を、それぞれ1ジェスチャーで1回だけ出す。指を離した時には出さない。
触覚非対応端末では表示・倍率操作のみを行う。1本指の戻る・縦横切り替えと2本指のピンチを区別する。

## 再現試験

`scripts/network-recovery-smoke.py` が、合成映像と合成音声を持つ85秒のCBR MKVを生成して、実際のReleaseアプリ・VLC・Rangeキャッシュ経路で再生する。
ループバックの通常速度を映像ビットレートより速い約512KiB/sへ制限し、全編の先読み完了前に障害を開始する。
再生位置4秒以降に、1MiBの応答を3回連続で9秒遅延する条件と、ソケットを切断して次の要求で回復する条件を別々に試す。
音声・映像の進行、待機表示、入力の再読み込み、VLCの警告を保存する。端末固有のハードウェア復号・携帯回線の切り替えを完全に再現する試験とは区別する。
