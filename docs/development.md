# 開発と実機確認

## ビルド

Swift / UIKitの型検査・テスト・ビルドは `.github/workflows/ios.yml` のmacOSランナーで行う。
Xcodeは26.6、CocoaPodsは1.16.2に固定している。Node / Metro / React Nativeは使用しない。
VLCKitは `ios/VLCKit.podspec` の公式ダウンロードURLとSHA-256で固定する。

Actionsの `NeoEPGStation-iOS-<run number>` ArtifactからZIPをダウンロードし、
中の `NeoEPGStation.ipa` をLiveContainerに取り込む。
このIPAはad-hoc署名であり、LiveContainerでの取り込み用。通常の直接インストールやApp Store提出には使わない。
バンドルIDを維持して更新し、接続設定が残ることも確認する。

シミュレーターはXcodeのad-hoc署名を使う。Releaseビルドを起動し、
接続設定のKeychainへの保存・読み戻し、直後に終了しないこととスクリーンショットを確認する。
加えて合成動画のVLC再生、コメントのMetal/CPU合成、横画面レイアウトを検証する。
基礎UIは実際のReleaseアプリをiPhoneシミュレーターで起動し、
架空の録画データを使った一覧・ページ7・詳細・サイドメニュー・設定の画像を生成する。
画面全体からのスワイプの40％／60％判定、詳細の戻る操作の完了・キャンセル、
タブの先頭から別タブへ戻らないこと、タブ切り替え後の詳細保持・検索結果から同じタブ内への戻り、
一覧の500ms／キャッシュ320msのフェード、遅延・共有ダウンロード・セル再利用を検証する。
iPadシミュレーター検証は手動実行の `check_ipad` で追加できる。通常のpushでは省略する。
モバイルの連続5ページ、iPadの省略付きページ番号、URL正規化、番組日時をSwiftのテストで検証する。
画面切り替え時に同じ一覧インスタンスが保持されることもシミュレーターで検証する。
下部ナビの項目・順番はUserDefaultsに保存する。実装範囲は `ui-foundation.md` を参照する。

生成済みビルドのrun IDを指定すると、保存したシミュレーター用アプリでiPad UIのみを再確認できる。

これは実サーバー接続・実機のAV1性能・バックグラウンドPiPの試験にはならない。
依存ロックファイルはActionsで生成した内容を検証して保存する。

## 最初の試験

1. 初回は接続設定画面が表示される。保存済みなら同じ接続先から録画一覧を自動で取得する。
   接続失敗時は保存URLを残した接続画面へ戻り、再試行・変更できる。
2. サーバーURLだけを入力して保存・接続する。
   URLには `/api` を指定しても除去される。サブパスは保持する。
3. 録画を検索し、一覧末尾のページ番号で移動する。番組を選び、詳細のPLAYでファイルを選ぶ。
4. 元ファイルのPLAYで映像・音声、再生／一時停止、±10秒・±30秒、シークバーを確認する。
5. 字幕トラックの選択とオフを確認する。PiPボタンが有効になったら開始・復帰を確認する。
6. 閉じた後に再度再生できること、再起動・IPA更新後に接続ボタンを押さずに録画一覧が開くことを確認する。

PLAYのネットワークキャッシュ（先読み）は初期値5秒。
別に巻き戻し用の一時ファイルキャッシュを設け、オフ／30秒／1分／2分／3分／4分／5分を選べる。初期値は1分。
Rangeに対応する録画済みファイルで利用し、録画中・ローカルファイルでは使用しない。
プレイヤーを明示的に閉じた時に一時ファイルを削除し、新しい再生の開始時に前の再生で残ったファイルを清掃する。
画面ロック・バックグラウンド移行・時間経過だけでは削除しない。保持時間による範囲外の破棄と容量上限は維持する。
再生中はバックグラウンドでも入力と音声を維持し、自動PiPを準備する。PiP開始待ちや開始失敗だけで停止しない。
一時停止中にPiPなしでバックグラウンドへ移る時は読み取り接続を停止し、復帰時に接続とVLC入力を再作成して停止位置を復元する。
通常字幕のオフ／選択名は次回へ保存する。全般の「コメントの準備を待って再生」は初期値オフ。
オンの場合はコメントの取得・解析・行配置・現在位置の文字画像を準備してから開始する。
コメント非表示・コメントなしでは待たず、取得失敗や15秒の期限でも再生を開始する。
NicoJKコメント専用描画とサイズ・不透明度の試作は `docs/comment-rendering.md` を参照する。
横画面では映像を左右のセーフエリア内に収めて下端まで表示し、操作欄は映像に重ねる。
映像をタップすると操作欄が切り替わり、最後の操作から2.5秒で隠れる。
再生終了時は操作欄を表示し、自動非表示を止める。終了後もタップで表示・非表示を切り替えられる。
PiPボタンは専用コメントを合成する経路を使う。通常のVLC字幕はまだ合成対象ではない。
新しい操作画面、情報パネル、回転固定、リロードの範囲は `player-ui.md` を参照する。
STREAMING、放映中は後続の実装対象。

視聴履歴はWebと同じ `/api/recorded/{id}/playback` へ送信する。
アプリの設定で「視聴履歴のユーザーを選択」からWebで使用するユーザーを選ぶ（初期値master）。
masterにはWeb側が履歴登録を許可しないため、保存には通常ユーザーの選択が必要。
ユーザー一覧には「master（すべて）」も表示し、masterへ戻せる。
「視聴履歴を送信しない」をオンにすると、通常ユーザーを選択していても送信しない。
初期値はオフ。ユーザー選択と送信しない設定は接続先ごとに保存する。
再生位置・長さ・セッションの実視聴秒数を送り、シークで飛ばした時間は視聴秒数に加算しない。
Web側の履歴有効設定・保存上限に従う。Webの認証セッションを自動で取得する機能ではない。

## ネットワークと保存

接続情報はSwift経由でKeychainに保存する。認証情報はURLに埋め込まず、診断ログへ出力しない。
旧試作のBasic認証情報は読み戻さない。URLの再保存で旧情報も置き換わる。
リバースプロキシのOAuthログインと認証セッションの引き継ぎは将来対応であり、現在は未実装。
oauth2-proxyはセッションCookieを使うため、ブラウザーへの遷移だけでAPI・VLCの認証が成立したとは扱わない。
参考: https://oauth2-proxy.github.io/oauth2-proxy/features/endpoints/
任意のユーザー指定HTTPサーバーに対応するためATSのHTTP制限を許可している。
HTTPSの証明書検証は無効化しない。App Store提出時にはこの設定の必要性とプライバシー情報を確認する。
ログ・スクリーンショットを公開する場合は、サーバーURL・番組名・認証情報等を確認してから共有する。
