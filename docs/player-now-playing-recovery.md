# ロック画面操作・復帰・センター表示中のコメント：ビルド96

## 変更

- `MPNowPlayingInfoCenter`へ番組名・局名・局ロゴ・再生位置・長さ・速度を登録する。`MPRemoteCommandCenter`の再生、停止、切り替え、10秒送り／戻し、絶対位置シークを通常のVLC制御へ接続する。終了時には自分の操作登録と情報を解除し、古いセッションが新しいカードを消さないようにする。
- 明示的な操作と復元完了時には、現在の`isPlaying`にかかわらず最新の再生／停止命令をVLCのキューへ送る。遅い状態通知でも意図と実状態の不一致を確認し、同じ命令の自動再送は毎秒までに抑える。復元中の操作も保存し、復元後に反映する。
- 復元シークは初期バッファ準備が終わってから開始する。同じ再生速度を復元のたびに設定し直さない。保持キャッシュの保持・削除条件は変更しない。
- 通常コメントのMetal描画は`willResignActive`で停止せず、`didEnterBackground`で停止する。コントロールセンター・通知センターによる非アクティブ化と実際の背景移行を区別する。
- PiP自動開始と手動フォールバックの重複を防ぎ、開始失敗のドメイン・コード・映像供給状態を診断に記録する。復元開始時の準備状態と実際に送った再生／停止命令も記録する。

VLCの時刻通知はデコーダースレッドで内部ロック中に届くことがある。その場で`isSeekable`等を問い合わせず、再生情報の更新はメインスレッドの通常タイマーと状態変更で行う。OSの遠隔操作受付もメインスレッドを同期的に待たず、操作を非同期で渡す。

## 実機で残る確認

シミュレーターではライフサイクル処理を直接呼んでいる。実際の画面ロック・OS休止からの復帰、ロック画面のカードと操作、センターを表示中のコメントの見え方、自動PiPは未確認。OSのPiPが非対応なシミュレーターで合成が通ったことを、実機のPiP成功とは扱わない。

実データの復元で先頭付近から大量に読み直す量が減ったかは、初期準備待ちの変更だけでは確認できていない。変更後の診断には準備完了と復元開始、再生意図・命令、Range読み出し量、映像再開が残るため、それらを対応させて確認する。

実機では、一時停止してロック／ホーム移行、復帰、10秒巻き戻し、再生／停止の順に確認する。再生中のロック画面操作と、コントロールセンター・通知センターを重ねる操作も確認対象とする。診断は自動送信せず、URL・認証情報・番組名・コメント本文は記録しない。
