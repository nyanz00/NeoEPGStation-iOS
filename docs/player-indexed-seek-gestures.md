# MKVの途中再開とプレイヤー操作

縦横のスワイプは指を離した時に確定する。縦から横は動画下端を固定して上のセーフエリアを埋める位置まで拡大し、その位置で止める。横から縦は動画サイズを変えず移動量を制限しない。下への移動が高さの35％に達した状態で指を離すと縦へ戻る。キャンセル時は復元する。ドラッグ中は操作UIを隠し、下の情報パネルは動かさない。

回転時はルートの座標変更に合わせて子コンテナとコンテンツの中心を一緒に再配置する。動画サイズと角度は既存の短いアニメーターで変える。レイアウト用のセーフエリアはルートから取得し、変換中の子ビューの値を参照しない。終了時に合成変換を等価な通常配置へ戻し、映像領域の座標差を `ui.rotationHandoff` に記録する。

動画背景の左右ダブルタップは `jump:-10` / `jump:10` を既存のシークへ送る。シングルタップはダブルタップ判定を待って操作UIを切り替える。ボタン、シークバー、情報パネル、左メニューは背景判定から除外し、横・縦のパンを優先する。Web側の `useTouchPlayerControls.ts` と `RecordedPlayerCore.ts` を確認した。指を離してからの縦横切り替えとダブルタップは、明示されたネイティブ独自操作として実装する。

コメントの初期文字画像と近傍の配置を描画スレッド外で準備する。既に移動しているコメントは配置候補の再生成・再測定を重複させない。退場だけなら配置を再構築せず、同じ表示集合・画像世代のフレームはキャッシュの再検索を省く。短いバッファリング通知だけで移動時計を止めず、映像更新の鮮度と明示的な停止希望で制御する。`comments.frameWork` は1秒ごとに短いフレーム間隔の乱れ・描画処理時間・GPU待ちを集計する。画面録画による操作感と実機の性能確認は自動試験と区別する。

MKVはEBMLヘッダー・Segment・SeekHeadからInfo、Tracks、Cuesを限定して読む。動画トラックのCue時刻、Segment相対位置、ファイル範囲、位置の単調性、先頭と末尾のCluster IDを確認した場合だけ、同梱VLCの `mkv_trusted` demuxを使う。索引なし・不正・未対応構造では通常の入力経路を維持する。MP4/TSにはこの指定を加えない。キャッシュの秒数管理は実際のシーク位置を指定する処理ではない。

VLCの通常MKV経路はCuesをQUESTIONABLE扱いし、HTTPのCAN_FASTSEEK=falseでは索引点の検証を省き、先頭側へフォールバックする場合がある。参照した上流ソースは `modules/demux/mkv/matroska_segment.cpp`、`matroska_segment_seeker.cpp`、`mkv.cpp` と `modules/access/http/access.c`。同梱フレームワークに `mkv_trusted` が含まれることも確認した。

`mkv.indexReady` は索引件数と数値の位置、`mkv.indexSeek` は目的時刻と予想Cue位置、`mkv.nativeSeek` はVLCが選んだ開始時刻とバイト位置を記録する。接続先・番組名・ログ本文は記録しない。

取得済みのEBMLヘッダーとInfo/Tracks/Cuesのデータは、VLCから同じ範囲を要求された時に再利用する。メタデータの読み取りは `indexReadBytes` として映像のディスクキャッシュ読み取りと分ける。プレイヤー終了時に破棄する。

復旧の25秒期限を過ぎても準備中の入力が停止・エラーになっていなければ保持する。期限で読み込み表示を解除し、遅れて初期一時停止とバッファ完了が来た場合は同じ入力を復旧済みにする。準備中に再生を指定した場合も、その入力の準備を再び待ち、新しい入力の読み直しを重ねない。明示的な再読み込みと実際の入力停止・エラーは従来通り扱う。

合成MKVのHTTP試験では90秒のCue付近へのRange要求、ファイル全体の半分未満の再取得、元ファイル時刻の保持、映像と時刻の進行を確認する。末尾の索引取得だけをシーク成功と誤認しないよう、目的Cueの近傍にあるRange開始位置を判定する。期限後の遅れた準備完了では入力インスタンスと再読み込み世代が変わらないことを試験する。
