# 読み込み済み範囲とナビゲーション

## 動作

- 読み取り接続・動画取得の警告は、対応する接続再開・データ取得成功で解除する。警告が消えた後、操作画面に残った同じ文言も通常の再生状態へ戻す。別の保存失敗の警告は通信の復旧だけでは解除しない。
- アプリ起動時は左メニューを閉じた位置に直接配置する。実際の開閉・スワイプでは従来のアニメーションを維持する。
- 下部ナビ・共通サイドメニューの項目を押すと、その項目の保持している一覧に戻る。詳細を開く前のページ番号・スクロール位置を維持する。検索から開いた詳細は、その検索一覧へ戻る。
- 同じ一覧を表示中にもう一度押すと、その一覧の1ページ目の先頭へ移動する。検索条件は維持する。別タブから戻っただけではページ番号をリセットしない。
- PLAYのシークバーに、取得済みの動画データから求めた概算の時間範囲を白（70%）で重ねる。未取得部分は白（35%）、再生済み部分はテーマカラー。離れた範囲の間にある未取得の隙間は塗らない。

既存のMP4索引・TS時刻・Matroska時刻の対応を利用する。映像・音声がすべて揃ったことを保証する帯ではなく、取得済みデータの目安である。対応する時刻が不明なデータやヘッダーだけを取得した範囲は塗らない。表示のための通信やファイル全体の読み直しは行わない。

取得・破棄の更新を200ms単位でまとめ、保存している時間範囲だけを統合する。毎フレームの全ファイル検索は行わない。保持キャッシュをオフにした場合も、先へ取得したデータの時間情報だけは表示用に保持し、再生位置より過去になった情報は破棄する。

## 検証

ネイティブテストで時間区間の統合と未取得の隙間を確認する。既存のRange試験で通信警告の解除・保存警告の維持・接続再開による警告解除を確認する。

iPhoneの操作試験で、起動時のメニューがアニメーションしないこと、詳細からページ7とスクロール位置への復帰、二回目の操作によるページ1への移動、別タブからのページ保持、検索結果からの復帰を確認する。プレイヤーの描画試験で、範囲間の隙間、全長変更時の再配置、取得範囲の消去を確認する。

Actionsのビルド・シミュレーター検証結果と実機検証は区別する。
