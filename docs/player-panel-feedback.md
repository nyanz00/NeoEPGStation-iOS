# プレイヤー設定・配信選択・ライブコメントログ

- コメント設定はコメント選択欄だけを先頭へ移動する。ほかの項目の相対順序は維持する。
- 配信ダイアログのタイトルはWebの RecordedSelectStreamDialog / OnAirSelectStreamDialog / programDialogStyles を参照し、20pt・700・行高30ptを使う。Webで生成されるCSSではレスポンシブのpaddingがpyを上書きするため、上下左右は幅600pt未満で16pt、以上で24pt。1行のタイトル領域は62pt／78ptに合わせる。複数行も行高に合わせる。
- 放映中は外部アプリ選択と外部URL起動を取り除く。
- iPadの右パネル閉じるボタンは右端の安全領域と8pt余白を基準に置き、44ptの押下範囲を維持する。iPhoneの配置を変更しない。
- エンコード済みSTREAMINGの弾幕と通常字幕を分離し、1回のトラック一覧取得から両方を構築する。弾幕の選択値を起動コンテキストへ渡し、初回の読み込みで適用する。明示した弾幕なしは、表示設定全体をオフにせず、その再生だけを弾幕なしにする。選択したトラックがなくなった場合は別トラックへ黙って切り替えない。
- ライブの投稿時刻をpostedAtとして保持する。ログはHH:mm:ss、描画は動画相対の時刻で扱い、両者を混ぜない。ライブに時刻がない場合は経過秒へ誤置換しない。
- ライブの追従中は読み込んだ最後の行を下端へ追従する。録画は再生時刻に対応する行へ追従する。「現在のコメントへ戻る」で追従を再開する。過去ログ閲覧中は安定した行IDと画面内の位置を保持し、古いログの削除によるジャンプを防ぐ。

対象確認はActionsのplayer-feedback。投稿時刻の伝搬、動画相対座標の維持、iPhone/iPadの閉じる配置、設定順序、追従復帰・手動閲覧、配信ダイアログの選択、HLS上で選択B/弾幕なしの初期再生、ライブTSの関連試験を実行する。再生環境は合成データを使い、実際の放送受信やアプリ外PiPのOS動作と区別する。

## ライブ操作・字幕・ログ保持の更新

- 放映中の配信選択はキャンセルボタンと背景タップの両方で閉じる。カード内部のタップは背景キャンセルにしない。
- 放映中のカード一覧の横スワイプで隣の放送波へ移る。先頭の放送波にいるときの右スワイプだけ既存のメニュー操作へ渡す。移動先が先頭になった同じ操作でメニューまで開かない。縦スクロールと既存の他ページの戻る操作を維持する。
- 放送波をボタン／スワイプで変更したら一覧を先頭へ戻す。同じ放送波の定期更新ではスクロール位置を保持する。
- TSのPLAY／STREAMINGとライブでは字幕ボタンでARIB字幕を直接オン／オフする。実際の字幕選択と保存・復元処理を使い、無効時はSubtitlesOutlined、有効時はSubtitlesを表示する。エンコード済みファイルでは字幕選択を維持する。
- ライブの閲覧用ログは描画タイムラインと分離する。通常は最新500件、手動閲覧中は古いログの削除を止め、追従復帰時に最新500件へ整理する。閲覧ログに60秒の期限を設けない。描画用データは従来どおり表示終了後60秒と2,000件の上限を持つ。
- プレイヤーを閉じるとログを解放する。ライブ入力の再初期化時には新しい入力の相対時計に合わせてログをリセットする。Web本体の保持条件は今回の変更に含めない。

タイトル寸法の訂正：build305の試験はアプリの42ptを確認していた。実際のWeb CSSはスマホ幅でpadding16px、広い幅で24pxが適用され、行高30pxを含め62px／78pxになる。今回の試験は描画後のタイトル領域をこの独立したWeb基準と照合し、画像・寸法JSONを保存する。

対象検証はplayer-feedbackのまま拡張する。Foundationではログの500件保持・手動中の保護・復帰を確認する。実際のiPhone/iPadシミュレーターでは最新行追従・手動位置・字幕アイコンと通常字幕選択・タイトル寸法を確認する。ライブTS試験では配信選択のキャンセル、放送波の移動・先頭復帰・更新時位置、MPEG-2／H.264のARIB字幕ボタンと実トラック選択を確認する。
