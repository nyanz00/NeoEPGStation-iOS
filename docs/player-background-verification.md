# PLAYのバックグラウンド移行とシーク診断

## 変更範囲

- 再生中のホーム移行では自動PiPを準備し、開始通知が遅れたりPiPを開始できなくても入力・音声を止めない。画面ロック中も音声を継続する。
- 一時停止中の復帰では停止位置と設定を維持する。キャッシュの削除条件は変更しない。
- PiPを画面の外へ避けた場合や通知センター等で画面が覆われた場合は、実際のデコード供給と再生状態からコメントを継続する。実際のバッファリングでは停止する。
- PiP用の準備画像が通常映像の背景に露出しないようにする。復帰時にインライン表示の古い画像を破棄し、VLCの外側の枠を動画領域に合わせる。
- バッファリング通知を最大10回／秒へ集約し、元の通知件数を記録する。メインキュー・UI・JSON・PiP状態の更新を通知全件分行わない。
- シークと保持キャッシュのアルゴリズムは維持し、Range接続ごとの読み出し量・送信処理完了量、内部のプリロール・バッファ準備・デコーダー待ち、最初の映像サンプルと映像再開を記録する。

## 実機での確認

シミュレーターでライフサイクル処理を呼ぶ検証は、iOSによる本当のバックグラウンド移行・ロック・PiPウィンドウの確認とは区別する。自動PiPにはiOS側の利用可否と設定も関係する。

1. エンコード済みPLAYで右パネルを開いた状態からホームへ戻り、PiP開始と音声継続を確認する。アプリに戻り、パネルを閉じた後の映像サイズと古い背景の有無を確認する。
2. 再生中に画面をロックし、音声が続くことと、復帰後の現在位置を確認する。一時停止してロックした場合は復帰しても一時停止を維持することを確認する。
3. PiPを画面の外へ避けて戻す操作と、アプリ内で通知センター／コントロールセンターを重ねる操作で、コメントが再開時に停止位置から飛ばないことを確認する。
4. 十分再生してから10秒巻き戻し・範囲外シークを行う。停止してホーム移行・復帰した後にも同じ操作を行う。
5. 遅延や不具合が残る場合は、直後に全般の「再生診断ログを共有」からJSONを保存する。通常起動との比較には同じファイル・同じ設定を使う。

ログは自動送信しない。URL・認証情報・番組名・コメント本文・生のVLCデバッグメッセージは記録しない。
