# エンコード

| 個別追加 | 一覧/詳細のメニューと詳細のENCODEボタンを同じフォームへ接続。元ファイル、プリセット、保存先、サブディレクトリ、同じ場所へ保存、元ファイル削除、サムネイル再生成。前回の設定を保存し、無効になったプリセット/保存先は現在の先頭値へ補正。元ファイルIDとサブディレクトリは録画ごとに初期化。 |

使用APIは`GET /encode?isHalfWidth=...`、`POST /encode`、`DELETE /encode/{id}`、`POST /encode/{id}/retry`、`PUT /encode/order`。プリセットと保存先名は`GET /config`の`encode`/`recorded`を使用する。API接続先や実際の録画で変更操作を行う試験は含めない。

Web同様、Socket.IOの`updateEncode`と`updateStatus`でエンコード情報を再取得する。通知専用のEngine.IO v4 HTTPロングポーリングを使い、更新がない間の3秒ごとのAPI取得は廃止する。設定されたSocket.IOポートへの接続が失敗した時はWeb同様にAPIと同じ接続元へ切り替える。サブパスを維持し、接続・再接続の完了時にも再取得する。タブ非表示・バックグラウンドでは接続を止め、復帰時に再開する。取得中に通知が届いた場合は、取得後に一度追加取得して取りこぼさない。更新対象のID・順序が同じ間はセルを維持し、文字スクロールを再起動しない。

局名は`/channels`を取得して局IDから解決する。取得失敗時はWeb同様に局IDと警告を表示し、更新操作・復帰時に再試行する。カードはユーザー指定の配置へ変更し、文字幅のバッジを左寄せ、三行の情報とサムネイルの縦中央を一致させ、キャンセルを%の直上に置く。タイトルは放映中と共通の一方向スクロールとし、末尾から先頭へは瞬時に戻る。復帰時には停止したアニメーションを再開する。

同じユーザー・資格情報の認証再確認では、ユーザー識別の世代とフォーム入力を保持して送信だけを無効にする。検証完了後に操作を再開する。送信中のPOSTを自動再送せず、次の一括追加は認証完了まで待つ。実際のユーザー・資格情報・サーバー変更では古い操作を中断する。広い画面のドラッグはHTMLドラッグの代わりにUIKitのドラッグを使用する。字幕・プレイヤー・エンコーダー本体は変更しない。

検証は`player-feedback` / `encode`に限定する。Foundationのジョブ生成・設定保存・部分失敗・操作順序・API契約と、模擬APIを使うiPhone/iPad画面試験、両SDKの型検査/ビルド/ライブラリ参照検査を対象とする。ビルド・模擬試験の成功と、実機・実サーバーでの処理成功は区別する。
