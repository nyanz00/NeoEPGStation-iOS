# エンコード

参照したWebソースは`RecordedPage.tsx`の`RecordedEncodeDialog`、`RecordedDetailPage.tsx`、`RecordedBulkEncodeDialog.tsx`、`recordedBulkEncode.ts`、`storage/encode.ts`、`EncodePage.tsx`、`EncodeRecoverySection.tsx`、`encodeBulkCancel.ts`、`programDialogStyles.ts`、`SocketBridge.tsx`、API型・クエリ・`EncodeApiModel`。

| 対象 | ネイティブ実装・確認点 |
| --- | --- |
| 個別追加 | 一覧/詳細のメニューと詳細のENCODEボタンを同じフォームへ接続。元ファイル、プリセット、保存先、サブディレクトリ、同じ場所へ保存、元ファイル削除、サムネイル再生成。前回の設定を保存し、無効になったプリセット/保存先は現在の先頭値へ補正。元ファイルIDとサブディレクトリは録画ごとに初期化。 |
| 一括追加 | 選択中録画に共通するファイル名から各録画の元ファイルIDを解決。録画中/共通元なし/設定なしは無効。順番に追加して進捗を表示し、部分失敗後は設定を固定して失敗したジョブだけ明示的に再試行。成功済みジョブを再送しない。 |
| 出力先 | 同じ場所へ保存する時は`parentDir`と`directory`を省略し、サーバーが各元ファイルの場所を解決する。通常保存では保存先名とトリムしたサブディレクトリを送信する。 |
| 一覧 | エンコード中、待機中、開始予約、要確認を分ける。サムネイル、番組/局/日時、モード、開始予約ラベル、進捗/ログ。進捗がない時は未確定表示。モバイル/広い画面の配置と操作表示を切り替える。 |
| キャンセル | 個別確認、一括選択/全選択/終了、完了数を表示。待機/予約中を先に、実行中を最後に順番にキャンセルし、失敗したIDだけ選択を残す。要確認の削除は選択モードから独立させ、失敗時は確認画面を維持する。 |
| 並べ替え | 待機中だけを上下ボタン、広い画面ではネイティブのドラッグでも移動。開始時のID順を`expectedEncodeIds`として送信。変更なし/重複/欠落/最新キューとの不一致は保存不可。サーバー409では編集を終了して最新の順番を再取得。 |
| 要確認 | サーバーが`canRetry`を返すものだけ再開ボタンを表示。削除は別の確認画面。番組/モード欠落時の代替表示と理由を表示する。 |
| 認証・反映 | 操作開始時のAPI/ユーザー/資格情報/世代を固定。ユーザー切り替えで中断し、古い応答を新しい画面に反映しない。追加/停止/完了時に録画データを無効化して一覧・詳細へ通知。変更要求の自動再試行は行わない。 |

使用APIは`GET /encode?isHalfWidth=...`、`POST /encode`、`DELETE /encode/{id}`、`POST /encode/{id}/retry`、`PUT /encode/order`。プリセットと保存先名は`GET /config`の`encode`/`recorded`を使用する。API接続先や実際の録画で変更操作を行う試験は含めない。

WebのSocket.IO更新通知に代わり、アプリではタブ表示中かつ前面にある間だけ3秒間隔で更新する。画面を離れるとタイマーと読取要求を停止する。広い画面のドラッグはHTMLドラッグの代わりにUIKitのドラッグを使用する。字幕・プレイヤー・エンコーダー本体は変更しない。

検証は`player-feedback` / `encode`に限定する。Foundationのジョブ生成・設定保存・部分失敗・操作順序・API契約と、模擬APIを使うiPhone/iPad画面試験、両SDKの型検査/ビルド/ライブラリ参照検査を対象とする。ビルド・模擬試験の成功と、実機・実サーバーでの処理成功は区別する。
