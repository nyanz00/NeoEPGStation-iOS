# コメント専用描画の試作

PLAYのNicoJK ASSコメントを、Swift / CoreText / Metalで表示する。
通常字幕と映像デコードは引き続きVLCKitを使う。動画と生のASSをJavaScriptへ渡さない。

## 利用と比較

- 再生時に `/api/videos/{id}/subtitles` からNicoJK・実況等の名前を持つASSトラックを探し、
  `/api/videos/{id}/subtitles/{subtitleIndex}/text` からテキストを取得する。
- 最初の該当トラックを専用描画で表示する。「コメント」でオン・オフ、文字サイズ（0.5〜2倍）、
  不透明度（0〜100%）、トラック変更・再読み込みを操作する。設定はこの再生セッション内で保持する。
- 専用描画が使えるときだけ、VLCの該当コメントトラックを解除して二重表示を防ぐ。
  通常字幕の選択は維持する。VLCの「字幕」からコメントトラックを明示選択すると専用描画をオフにする。
- サーバーの字幕APIが使えない場合、未対応ASS、文字画像の生成失敗、キャッシュ容量超過は理由を表示する。
  専用描画でコメントを間引く代わりに、VLC側の表示を利用できる状態にする。

## 描画と同期

- ASSのPlayRes・開始時刻・文字・スタイル・縦位置を読み込む。
- コメントの終了時刻はASSから使わず、Web版DPlayerの全画面・速度1倍と同じく、
  流れるコメントは5.5秒、固定コメントは4.5秒で表示する。
  CMカットで元の表示時間が短縮・ゼロになったコメントも通常の表示時間でCM明けまで残す。
  開始時刻が不正な場合はエラーにする。ASSの位置や表示区間を忠実に再現する一般字幕の経路とは分ける。
- 流れるコメントの横位置は右端から実際の文字幅を含めて左端外まで移動させる。
  ASSのmove時間指定と終了座標は使用しない。固定コメントの位置、コメントの縦位置はASSから保持する。
- CoreTextで文字画像を別キューで作り、再利用する。画像キャッシュは48MiBを上限とする。
- MTKViewは60fpsを要求し、毎回文字を画像化せず、Metalでテクスチャの位置と不透明度を更新する。
  文字の移動は動画のフレームレートから独立し、VLCの再生時計に従う。
- VLC時計は1/60秒間隔で更新する。補間は最大50msまでに制限し、停止・バッファリングで進み続けない。
- 区間木で表示中と1秒先のコメントだけを検索する。シーク後はその時刻から再計算する。
- 映像のアスペクト比とSARに合わせ、レターボックス部分へ描かない。

対応範囲はASS v4+の単一スタイルの文字、複数行、色・アルファ、太字・斜体、縁取り・影、
フォント・サイズ・縦横倍率、an、pos、move、q2。
未対応の変形・フェード・カラオケ・ベクター描画・文中の装飾変更等がある場合は、
トラックを専用描画の対象にしない。ASSの完全互換を保証しない。未搭載フォントはOSの代替フォントになる。

## PiPと検証の範囲

PiPには、VLCから受け取るデコード済み映像と専用コメントを合成し、
AVKitのsample-buffer PiPへ渡す。通常画面はこれまでのMetal描画を維持する。
再生セッション・音声・シークは同じVLCプレイヤーを使い、元ファイルを書き換えない。
コメント設定は通常画面とPiPで共有する。

現在は固定したVLCKit内の `VLCSampleBufferDisplayView.layerClass` を、独自の
AVSampleBufferDisplayLayerサブクラスへ差し替える試作アダプターを使う。
Appleのクラスやメソッドは差し替えない。VLC側のクラス名と元の戻り値を確認し、
構造が変わった場合はPiPを無効にする。VLCKit更新時にはフレーム取得テストを必ず行う。

PiP映像はSARを反映して最大960×540に縮小し、60fpsを要求してコメントを合成する。
CoreTextの文字画像をキャッシュし、バックグラウンドでMetal描画を要求しないCPU合成を使う。
映像の8/10bit YUV色変換はVideoToolboxを使い、変換セッションとBGRAバッファを再利用する。
受信フレームは8枚、出力プールは6枚を上限にし、詰まった場合は合成フレームを落とす。
この負荷とバックグラウンドでの継続は実機で確認が必要。

合成対象は専用描画のNicoJKコメント。VLCが別のビューで描く通常字幕は、現時点ではPiPに取り込まない。
映像に既に焼き込まれた字幕は映像として表示される。STREAMING・放映中の別字幕合成は後続の実装。

ActionsではASS解析・表示区間・シーク・時計をSwiftで検証する。
シミュレーターでは同じMetalシェーダーとCoreText処理で80コメントをオフスクリーン描画し、
非空画像、移動、同一時刻の停止画像、不透明度0、終了後の消去をGPU読み戻しで確認する。
`danmaku-smoke.json` と `danmaku-smoke.png` を診断Artifactに保存する。
PiP用の同じCPU合成処理でも移動・停止・サイズ・不透明度・オン／オフ・終了・映像の向き・
8/10bit YUV色変換とサンプル時刻を検証する。合成画像は `pip-composition-smoke.png` に保存する。
合成動画を実際のVLCで再生し、フレーム受信から連続合成・表示レイヤーへの出力までを検証する。
PiP非対応のシミュレーターでは小窓を開始せず、同じ合成キューを前景で動かす。
横画面のレイアウト制約と、VLCのリサイズ後の映像のフィットも確認する。
`pip-player-smoke.json` のPiP可否はシミュレーターの診断であり、実機でのPiP開始・継続の保証にはしない。
これは実機の描画性能や発熱・消費電力の検証ではない。

実機では同じ録画の同じ密集場面を専用描画とVLC字幕で比較する。
設定画面の描画更新fps・描画件数・キャッシュ使用量とともに、コメントの滑らかさ、
オン・オフ、サイズ・不透明度、シーク・一時停止、回転、再生終了後の再オープンを確認する。
PiP開始後にホームへ移動し、コメントが動き続けること、停止・再開・シーク・アプリへの復帰、
設定変更後の再PiP、PiPを閉じたときの停止も確認する。
