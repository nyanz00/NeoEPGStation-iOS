# 録画一覧・検索・履歴送信

Webの `RecordedPage.tsx`、`UserSelector.tsx`、設定ストレージ、APIの録画検索・候補・ルールキーワード処理を参照する。

- 表示設定の録画済み表示件数は初期値24、1〜1000。接続先ごとに端末へ保存する。取得limit/offset、ページ数、キャッシュ識別、履歴からのlistPositionで同じ値を使用する。
- 詳細へ進む前の一覧位置を保持し、戻った際は対象カードを約1秒強調する。履歴からの移動は対象ページを取得してカードを中央へスクロール後に同じ強調処理を使う。表示設定で両方を無効にできる。既定オン。色はMUI dark warning.main（orange[400] #FFA726）とaction.hover（白0.08）。セル再利用時に解除する。
- 一覧のユーザー選択は初期アクティブユーザー、masterは全件。選択を変更したらページ1へ移動する。一覧の選択は履歴送信先やプロフィール認証を変更しない。起動時のアカウント復元は、一覧で明示選択されるまで初期値へ反映する。
- 検索条件はキーワード、ルールのキーワード候補、チャンネル、ジャンル、複数ファイルタイプと「含む／のみ」、元ファイル、手動録画、drop/error/scrambling、録画日の期間または年/月/日。候補はWebと同じ録画optionsとrules/keyword API。日付はJST、終了日は同日末尾まで。存在しない日付や逆転期間を拒否する。
- スマホの検索は縦に並ぶフォーム。検索結果は元の一覧の上に保持し、詳細から検索結果へ、録画済みナビ操作で検索前の一覧へ、さらに押すとページ1へ戻る。キャンセルは条件を適用しない。検索のクリアは元一覧へ戻す。
- 巻き戻しキャッシュは1行のドロップダウン。オフ、30秒、1〜5分を維持し、保存値と保持処理は変更しない。
- 履歴のobservedAtはOpenAPI UnixtimeMSが要求する整数ミリ秒。通信・タイムアウトは「サーバーに接続できませんでした」、それ以外は「視聴履歴の送信中にエラーが発生しました」。HTTP番号、URL通信エラー番号、observedAt検証失敗を固定項目で診断へ記録し、応答本文や認証情報は出力しない。

検証はFoundationのAPI・日付境界試験、Releaseシミュレーターの一覧復帰・ユーザー独立性・ハイライト有効/無効/期限/セル再利用・検索条件保持、検索と表示設定の画面キャプチャで行う。再生試験の履歴サーバーは整数observedAtを検証する。実サーバー接続・実機操作とは区別する。
