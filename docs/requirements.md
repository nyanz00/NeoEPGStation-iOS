# iOSクライアントの要件と開発方針

## 対象と構成

- iOS / iPadOS 18以降。最終的にはApp Storeで公開する。
- サーバー、iOSクライアント、Windowsクライアントは別レポジトリとする。
- 管理画面・API通信はReact Native 0.87.1とTypeScript。ネイティブ連携はSwift。
- 再生はVLCKit / libVLC 4系を基盤に、必要な映像出力・字幕合成の改修を行う。
- 映像フレーム・字幕合成をJavaScript側へ渡さない。Objective-C / C / C++の連携も必要に応じて使う。
- 現在のVLCKitは公式4.0.0a25（20260929-1631）の未改修バイナリ。開発版である。

## 最終的な機能とUI

NeoEPGStationの機能と基本的なデザインを引き継ぎ、モバイル向けの操作を作り込む。
iPadはWeb版に近いサイドバーを基本とする。
iPhoneは表示項目・順番をカスタマイズできる下部ナビゲーションと、Web版の全項目を持つ左サイドメニューを使う。
両方の入口は同じ画面と状態を参照する。Twitterアプリの参考画像はナビゲーションの構成例であり、
配色やコンテンツの見た目はNeoEPGStationを引き継ぐ。
最初の基礎UIはWeb既定のターコイズ・ダークモードで作る。
カスタムカラー設定は後続で追加する。現在の実装範囲は `ui-foundation.md` を参照する。

左端から右へのスワイプは、開始位置が画面の上半分ならメニュー、下半分なら戻る、という案を最初に試す。
途中で中央を跨いでも操作を変更しない。戻る先がない画面では何もしない。
メニューボタンと戻るボタンも用意し、縦スクロール、横操作を持つ部品、プレイヤーのジェスチャーと競合させない。
メニューは背景タップ・左へのスワイプで閉じる。
画面幅・分割表示による切り替えとスワイプの使い勝手は、画面実装時に実機で確認する。

## サーバー接続

- 初回はサーバーURLだけを入力する。接続画面にBasic認証のユーザー名・パスワード欄を置かない。
- URLを端末に保存し、次回起動時にはその接続先から録画一覧を自動で取得する。
  失敗時は入力済みURLを残した接続画面で再試行・変更できる。保存・再接続を毎回要求しない。
- 旧試作のBasic認証情報は読み戻さず、API・動画再生へ自動で送信しない。
- リバースプロキシのOAuth認証は将来対応。まずoauth2-proxyを想定する。
  認証画面への遷移、ログイン完了後のアプリへの復帰、認証セッションの保存・期限切れを扱い、
  API・サムネイル・字幕・動画取得にも同じ認証を適用する。
  認証画面を表示するだけで対応完了とは扱わない。現在の試作にはこの経路をまだ実装していない。
  EPGPlayerの認証とVLCへのCookie受け渡しを参考にする。調査内容は `docs/server-authentication.md` を参照。

## 再生の重要要件

- PLAY: 元ファイルを再エンコードせず再生する。AV1のハードウェアデコードに対応しない端末で
  ソフトウェアデコードを試す。MKV、AV1 Main 10bit、AAC、ASS、1440×1080・約24fps、1920×1080を検証対象とする。
- PLAYの高ビットレート動画に対して、先読み・開始・再バッファリングの方針を調整する。
  回線の持続的な速度不足をバッファだけで解消できるとは扱わない。
- STREAMING: HLSを使えるようにする。モバイル回線向けに選択した品質で再生する。
  自動品質切り替えは必須要件ではない。
- 放映中: ネイティブでリアルタイム視聴し、停止検知・再接続・ライブ位置への復帰を実装する。
  WebKitの自動再生許可やMSEを通さない。
- 再生・シーク・全画面・PiPの操作を軽快にし、同じ再生セッションで移行する。
- 性能は実機で評価する。シミュレーターの成功を旧端末での性能保証に使わない。

## 字幕とコメント

- ASS / NicoJKの移動・位置・装飾を描画する。
- NicoJKコメントの表示時間はdanmaku側で決める。CMカットでASSの表示時間が短縮・ゼロになっても、
  通常の速さで流し切り、CM明けまで表示を継続する。
- 再生中のオン／オフ、トラック切り替え、サイズ・不透明度の細かな調整を可能にする。
- 字幕・コメントを表示時に映像と合成し、PiPでも表示する。元ファイルを書き換えない。
- 設定は通常画面とPiPで共通とする。PiPの小窓に独自の字幕操作ボタンは作らない。
- STREAMINGは字幕なしの映像と別取得の字幕を合成する。既存Web版の焼き込み経路は維持する。
- シークや再接続の後も映像・字幕の時刻を合わせる。放送字幕とASSは別の形式として扱う。
- 標準VLCKitの字幕表示・PiP対応だけで「コメント付きPiPが完成」とは判断しない。
  必要なlibVLC映像出力の改修と実機での検証を行う。
- コメントの専用描画はSwift / CoreText / Metalで試作する。現状の対応範囲と検証は
  `docs/comment-rendering.md` を参照する。通常字幕はlibass経路を維持する。

## 最小試作と段階

1. ActionsでReleaseのIPAを生成し、LiveContainerで導入・更新する開発サイクルを確認する。
2. 接続設定の保存 → 録画一覧 → ファイル選択 → ネイティブPLAY再生を成立させる。
3. AV1実データ、シーク、字幕切り替え、PiP移行、PLAYのバッファ挙動を確認する。
4. コメントのサイズ・不透明度の変更とPiP向けの合成を実装・検証する。
5. 全面移植の前に、字幕とHLSの同期、および1チャンネルのリアルタイム視聴を確認する。

LiveContainerは初期導入の手段であり、製品の最低OSや最終配布方式の基準にはしない。
初期試作はマスターの録画一覧を扱う。視聴者プロフィールの選択・ロック解除は後続の移植で実装する。
予約・ルール・番組表・アニメ等の全面移植は再生経路の検証後に進める。
