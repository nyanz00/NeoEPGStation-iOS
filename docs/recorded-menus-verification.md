# 録画メニューとドロップ表示の検証

検証済みソースは `8cce6af71aa6b02d8f6f138ec65e4f4c80396cb5`。
Actionsの[ビルド44](https://github.com/nyanz00/NeoEPGStation-iOS/actions/runs/37299959806)が成功した。
この記録の追加ではアプリ・ビルド設定を変更していない。

## 変更

- 録画カードの三点メニューを、Webの `RecordedItemActions` と同じ項目・順序・表示条件にした。
  押したボタンを基準に表示し、従来の「詳細」だけのシステムポップオーバーを廃止した。
- 録画詳細の右上にも同じメニューを追加し、詳細用のダウンロード項目を先頭に置いた。
- PLAYの選択欄はボタン直下に表示する。タイトル・説明・ファイルごとのサイズを外し、ファイル名だけの小さなボタンにした。
  UIKitの軽量なオーバーレイで開閉し、再生開始前にシステムモーダルの終了を待つ経路をなくした。
- ドロップ・エラー・スクランブルの件数と全ファイルの合計サイズを同じ欄に表示する。
  件数が非ゼロなら赤字・太字にし、ログがある場合はタップして本文を読む。
- 開いたサイドメニュー内、または外側の暗い領域で左へスワイプすると、指に追従して閉じる。
  メニュー内の縦スクロールと共存し、閉じる操作中だけ縦スクロールを止める。

三点メニューの管理操作は今回表示のみで、選択すると「準備中」の案内を出す。
サーバーの録画削除・保護変更・エンコード等は実行しない。

## 結果

Swiftの型検査、メニューの表示条件・順序、ドロップ情報のデコードと合計サイズ、
ログ取得のパス・クエリ・ユーザーヘッダー・成功／失敗応答の試験が成功した。
iPhoneのReleaseアプリで以下を確認した。

- 一覧の項目は `rule / search / user / encode / Info / protect / delete`、詳細では先頭に `download` が加わる。
- PLAYの項目はファイル名だけになり、選択欄の左端・上端がPLAYの左端・下端に一致する。
- ドロップ情報を持つ架空の録画は `drop: 2, error: 0, scrambling: 0 1.33 GB` と表示される。
- 選択欄を10回開いて選択し、コールバックが10回だけ呼ばれ、オーバーレイが残らない。
- サイドメニューの左ドラッグで位置と暗い領域の濃さが追従し、終了後に閉じる。
- 同じタブ内の戻る操作の完了・キャンセル、タブ間の詳細保持、検索から戻る操作が維持される。

一覧・ページ7・詳細・三点メニュー2種類・PLAY選択欄・サイドメニュー・設定の画像を生成し、
新しいメニュー3種類の画像も目視確認した。
一覧の500ms／キャッシュ320msのフェード、サムネイルの共有取得・セル再利用、
保存・VLC再生・コメント描画・PiP合成の既存試験も成功した。
サムネイル試験の遅延応答は、固定時間の待機から試験が明示的に解放する方式へ変更した。
本番のサムネイル取得処理は変更していない。

iPadシミュレーターは省略した。操作ハンドラーとUIKit表示の確認であり、
指での認識・開閉の軽快さ、実サーバーのログ表示、iOS 18実機上の動作は端末で確認する。
