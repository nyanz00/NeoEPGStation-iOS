# ページ遷移直後の戻るスワイプ

前回はメニューを閉じる背景のヒット判定だけを修正していた。共通シェルには別に、UINavigationControllerのtransitionCoordinatorが存在するとスワイプ開始を拒否する条件が残っていた。認識開始で拒否された同じ指の操作は、遷移完了後も再認識されない。

ビルド316ではpushの自然終了まで戻る操作を保持していたため、入力拒否は解消しても画面が指より遅れる待ちが残った。

現在はpushを公開APIのUIViewPropertyAnimatorで管理し、戻る開始時に表示中の位置を取得してpushの内部処理を即座に完了させる。次のrun-loopでその位置を開始進捗としてインタラクティブpopへ渡し、指の移動量を加算する。pushの残り時間は待たない。popのアニメーションの始点自体は0のままなので、キャンセル時も途中位置から通常の全画面へ滑らかに戻る。内部のpushとpopは重ねず、通常のpushアニメーション、pop中の二重操作防止、タブルートから別タブへ戻れない規則を維持する。別タブへ移った場合は保留状態と表示変形を破棄する。

短いドラッグがUIKitのインタラクティブ遷移コンテキスト作成より先に終了した場合も、既存のプレイヤー用ドライバーと同じく更新・終了をコンテキスト開始まで保持する。

検証は `check_scope=player-feedback`、`ui_stage=navigation`。両SDKビルドに加え、iPhone/iPadの実際のUIKit push開始50ms後と180ms後に設定・録画詳細の共通認識判定・ドラッグ処理を呼ぶ。pushが本当に進行中だったこと、自然終了の350msより前にpopへ切り替わること、presentation layerの画面位置が引継ぎ位置＋指の移動量に一致し次の移動にも追従すること、最初の操作でルートへ戻ること、キャンセル・短いドラッグで全画面へ戻り直後の次操作も使えることを検証する。タッチの当たり先も確認するが、実機の指による操作そのものを自動注入する試験ではない。

公開APIの停止・終了の扱いは[Apple UIViewAnimating](https://developer.apple.com/documentation/uikit/uiviewanimating/stopanimation(_:))に従う。私的なナビゲーションAPIやUIKit内部アニメーターの探索は使わない。

この対象指定では映像・字幕・ライブ配信の試験を実行しない。Web側は設定・ナビゲーションに今回のUIKit固有の遷移制御がなく、変更対象としない。
