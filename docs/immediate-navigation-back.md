# ページ遷移直後の戻るスワイプ

前回はメニューを閉じる背景のヒット判定だけを修正していた。共通シェルには別に、UINavigationControllerのtransitionCoordinatorが存在するとスワイプ開始を拒否する条件が残っていた。認識開始で拒否された同じ指の操作は、遷移完了後も再認識されない。

通常のpush中に始めた戻る操作は、同じナビゲーションと遷移先に限定して保持する。UIKitのdidShow後に、保持した移動量・指を離した状態を引き継いで戻る。pushとpopを重ねない。キャンセル・短い未成立ドラッグ・別タブへの移動では保持を破棄する。すでにpop中の場合の二重操作防止と、タブルートから別タブへ戻れない規則は維持する。

短いドラッグがUIKitのインタラクティブ遷移コンテキスト作成より先に終了した場合も、既存のプレイヤー用ドライバーと同じく更新・終了をコンテキスト開始まで保持する。

検証は `check_scope=player-feedback`、`ui_stage=navigation`。両SDKビルドに加え、iPhone/iPadの実際のUIKit push開始50ms後に、設定と録画詳細の共通認識判定・ドラッグ処理を呼ぶ。pushが本当に進行中だったこと、判定が受理されたこと、二重遷移せず最初の操作でルートへ戻ること、キャンセル・短いドラッグが後から再生されないこと、その直後に次のスワイプが使えることを検証する。タッチの当たり先も確認するが、実機の指による操作そのものを自動注入する試験ではない。

この対象指定では映像・字幕・ライブ配信の試験を実行しない。Web側は設定・ナビゲーションに今回のUIKit固有の遷移制御がなく、変更対象としない。
