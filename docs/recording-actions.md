# 録画済みの5操作

Web参照: `RecordedItemActions.tsx`、`RecordedDetailPage.tsx`、`programDialogStyles.ts`、`UserSelector.tsx`、設定・API・サーバーの録画/動画/サムネイル処理。字幕操作・encode・ruleは今回の対象外。

| 操作 | アプリ実装・反映 | 確認 |
| --- | --- | --- |
| download | 詳細の動画/プレイリスト別ボタン。認証ヘッダー付きの同じAPIから一時ファイルへ直接取得し、Filesへ書き出す。キャンセル・エラー・アカウント変更で一時ファイルを破棄する。 | ローカルHTTPサーバーでURL/ヘッダー/添付名/バイト一致/リダイレクト拒否/エラー/キャンセルを確認。大容量の実機保存は別途確認。 |
| user | 通常ユーザーのみ選択して録画の所有ユーザーを変更。アクティブユーザーは変えない。 | 模擬API・ダイアログで選択/送信/読込失敗と再試行/空/処理中状態を確認。 |
| thumbnail | 詳細THUMBとメニューの両方から元動画を選択して再生成要求。サーバーの受付後に閉じ、「開始しました」と表示。 | キュー受付と画像更新を分ける。最初30秒は2秒間隔、その後10秒間隔で最大10分、既存サムネイルIDの変更を確認して一覧/詳細を更新。生成完了や生成失敗を確定する専用APIはないため、受付・監視終了を完了通知とは扱わない。監視終了後も詳細への再訪で最新値を取得する。 |
| protect | 追加の確認なしで保護/解除APIを呼び、一覧・詳細・履歴の情報を更新。 | 204応答・保護/解除URL・二重操作防止・エラーを確認。 |
| delete | 初期選択設定（表示内）に従うファイル選択。全ファイル選択は録画削除、一部選択は動画を順番に削除。途中失敗時は削除済み分を反映し、残りを再選択できる。 | 模擬サーバーのみ使用。全体/一部/途中失敗/保護エラー/アカウント変更を確認。録画中の動画削除を録画全体の削除へ昇格するサーバー仕様も引き継ぐ。 |

ダウンロードはWebのブラウザー保存に相当するネイティブFiles書き出しで、外部プレイヤーのURLスキームには飛ばさない。Annict設定の「ダウンロード時の視聴記録」を有効にした場合だけ、録画/プレイリストの取得開始と並行して記録する。Annictの失敗はダウンロードを停止しない。

共通: 接続先・アクティブユーザーが変われば操作を中止する。既にサーバーで受理された変更は取り消せないため、キャッシュを無効化して最新値を取得する。古い取得結果が変更後のキャッシュへ戻らないよう世代番号を照合する。

検索フォーカスは`viewWillAppear`/`viewIsAppearing`で要求する。表示完了後の遅延タイマーは使わず、キーワード欄を再生成しない。シミュレーターでは`viewDidAppear`へ入る前にフォーカス済みであることを確認する。

検証スコープ: `player-feedback` / `recording-actions`。このスコープは録画操作・ダウンロード・検索フォーカスに限定し、再生/PiP/字幕/通信復旧の試験を走らせない。ビルド成功・模擬API成功と、実機での保存/サムネイル生成成功は区別する。
