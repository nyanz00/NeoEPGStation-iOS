# 録画詳細の初回表示とページ開始応答

## 成功条件

- 全般の「半角表示」（初期値オン）を一覧・履歴・詳細・関連録画・放映中の取得へ渡す。録画テキストの補正はサーバーの `StrUtil.toHalf` と同じ変換だけを使う。
- 準備済みの履歴・一覧から詳細へ入った最初の表示で、dropの値・強調色、文字表記、Annictヘッダーが一致する。未取得のdropは0として表示しない。
- Annictの記録・取り消し・再照合は共有結果へ反映する。接続先・認証世代の違う結果を再利用しない。
- ネットワーク未完了のまま開いても遷移を通信完了待ちにしない。データが不足していた場合は局所的に更新し、画面全体を再構築しない。
- 開始応答の目標はiPhone/iPadともハンドラーから最初の移動まで100ms以内。初回と準備済みを別々に記録し、従来の相対基準で成功としない。CADisplayLinkによる観測は実機の物理タップ測定ではないため、実機体感の確認と区別する。

## 実装上限

表示範囲の録画だけを先行取得する。2ワーカー（詳細・Annictを並行し最大4要求）、待機16件、結果各64件・60秒。画面自体の準備は詳細2件と設定の全般・視聴に限定する。先行取得とタップ時の要求は共有し、初回表示のための無制限な全件取得はしない。

履歴APIがdropを返さないサーバーもあるため、アプリ側で詳細を先行補完する。サーバー側の変更・アップデートは今回の条件にしない。通信前に一切得られていない情報を即座に確定表示できるとは扱わない。

## 対象検証

Foundationの変換・未取得値の試験、HTTPスタブを使う詳細準備・設定切替・認証変更・Annict更新の試験、両SDKビルド、iPhone/iPadの初回表示・ナビゲーションを確認する。再生処理は変更していないため、無関係な再生全体試験は実行しない。検証結果は実行後に追記する。
