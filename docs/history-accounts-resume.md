# 設定カテゴリ・アクティブユーザー・視聴履歴・リジューム

Webの SettingsPage、WatchHistoryPage、RecordedWatchPage、activeUser/viewerProfile storage、API定義を参照する。

- 設定入口をアイコン・説明・右矢印のカテゴリ一覧へ変更。実装済み項目をアプリ設定／全般／視聴／表示／アカウントへ分ける。未移植機能の空タブや設定検索は追加しない。
- 接続先・下部ナビはアプリ設定。ユーザー選択はアカウント。リジュームとアプリの履歴送信停止は視聴。保存件数は表示。
- 既存の接続先別ユーザーIDを継承する。通常ユーザーはユーザー一覧と連携プロフィールを照合し、保護されている場合は既存の解除APIへ連携パスワードを送る。成功前・キャンセル時は選択先を変更しない。
- セッションは接続先とプロフィールIDで分離してKeychainへ保存。パスワードは保存しない。保存済みセッションを確認し、失効時は削除して再認証する。起動・再アクティブ化時に確認するが、再生中のユーザーを勝手に変更しない。
- 将来の連携APIは共通のプロフィール・セッションヘッダーを使える。視聴履歴APIはユーザーIDだけで動かす。Annict・コメント投稿自体と録画一覧のユーザー絞り込みUIは今回未移植。
- 履歴はユーザー別の番組・局名・最終視聴・時間・進捗、詳細への移動、一覧の該当ページでの表示、削除、サーバー側保存有効設定を移植。masterは記録・取得しない。取得失敗時は同じユーザーの表示済みデータを維持し、ユーザー変更時は消去する。
- 一覧で表示する操作だけはWebの listPosition が返す所有ユーザーとページを使う。通常の一覧に新しい絞り込み操作は追加しない。
- 履歴送信はプレイヤーを開いた時のユーザーへ固定。シークで飛ばした秒数は視聴秒数にしない。プレイヤー終了・最終送信完了後に表示履歴を更新する。
- リジュームは既存APIで保存時刻を取得してから、最初の入力の start-time に指定する。冒頭5秒未満・終端10秒以内はWeb同様に0から開始。初期コメント取得も再開地点を基準にする。
- リジュームは既定オン。設定でオフにでき、録画詳細には最初から再生する操作を用意する。取得失敗時は再試行／最初から／キャンセルを選べる。通信応答を待つ間に画面やユーザーが変わった場合は起動しない。

検証: FoundationのAPIフィクスチャ（ヘッダー・有効性・履歴・途中時刻の境界）、シミュレーターのKeychain・保護ユーザー切替・認証失敗・セッション失効、実VLCのMKV90秒からの初回入力と映像進行、設定カテゴリ・履歴画面の画像。
ビルド成功と実サーバー／実機での認証・再生確認は区別する。
