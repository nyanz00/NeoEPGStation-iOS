# AV1 状態復元診断

設定 → アプリ設定 → 再生エンジンで「診断用：AV1状態復元」を選び、
エンコード済み AV1 の PLAY を開き、「診断を開始」を押す。
長い GOP の同じ動画を使う。対象は 1920×1080 以下。
通常の視聴経路、TS、STREAMING、コメント、PiP、視聴履歴は変更しない。
以前の「AV1復号比較」も別の項目として残す。

## 測ること

既存の準備処理で、先頭の実キーフレームから次のキーフレームの約 1 秒後までの
圧縮パケットを RAM に取得する。96MiB / 3,000 パケット / 65 メディア秒 / 90 秒の
準備上限を継承する。一時 MP4 は codec copy で、終了時に削除する。
通信・デマルチプレクス・MP4 作成は復号タイマーに入れない。

目的位置は最初の GOP の 90%。その約 2 秒前と約 0.25 秒前を保存地点とする。
短い GOP の場合は距離を縮める。実際のパケット境界・画像の時刻を結果に記録する。

- 同じ復号器を flush して、本物のキーフレームから目的画像を得る時間
- 保存した状態を同じ復号器へ復元し、残りだけ復号して目的画像を得る時間
- 状態の保存・参照再設定そのものの時間
- 1 地点が生存させる参照画像等のデータ量、復元を繰り返した後のプロセスの phys_footprint

各条件 5 回。通常の復号と比較し、全 Y/U/V の有効画素を行ごとに `memcmp` する。
入力との対応・出力数・画素形式も一致させる。本物の次のキーフレームを越えてから
戻す操作を 5 回実行し、状態の一時保存・解放も各回に行う。
空の復号器の保存、別の復号器への復元、状態なしの非キーフレームからの再開は
拒否されることを確認する。画素照合は速度計測の外で行う。

この試験は画像を取得するところまでで、音声同期・画面表示までのシーク時間ではない。
単一スレッド・フレーム遅延 1・既定の画像アロケーターで測る。
ハードウェア復号の状態を取り出す機能ではない。

## 結果と制限

「診断結果を共有」で `checkpoint-benchmark.json` を共有する。
2 条件とも成功した場合だけ `status=complete`。不一致・未対応・上限到達は `partial`、
準備失敗は `failed`。ソース URL・タイトル・画像・認証情報は結果に入れない。
各行の `status=0` が成功。1001 は入力、1002 は境界、1003 は画像等の不一致、
1004 は目的画像/後続キーフレームなし、1005 はデータ保持上限、1006 は中断、
1007 は 180 秒の実行上限、1008 はネイティブ復号処理の失敗（`decoderError`）を表す。

`retainedBytes` はプールブロックを重複除去した保持量で、保存時の追加確保量とは違う。
`sampledFootprintBytes` は各復元・照合後のプロセス全体の観測値で、アロケーターの
キャッシュ等も含む。増加があるだけでリークとは判断しない。標本の最大値は厳密な
ピーク使用量ではない。開始前後の thermalState も記録するが、消費電力は測っていない。

保持状態は同一プロセス内のみ有効。HDR メタデータを持つ境界・未処理出力・不完全な
パケットは対象外。閉じる、バックグラウンド移動、メモリー警告で中断し、同期的な
ネイティブ処理が中断点へ戻ってから全参照・復号器・一時ファイルを解放する。

## ビルドと分離

`scripts/build-checkpoint.py` は dav1d 1.5.4 の
`54706fc6bc0cdecab7e9593974a4039cc038fca7` を固定する。
PC 実験と同じ `experiments/dav1d-checkpoint/checkpoint.c` を使い、アプリとの境界は
`vendor/checkpoint/NeoCheckpointLab.h` の単純な C 型だけとする。
全 public dav1d API を `neo_lab_` 接頭辞へ変更し、Apple 側ではシンボルを非公開にする。
通常再生がこの改造版へ結び付かないよう、既存の動的 AetherLibdav1d とは分離する。
ライセンス・固定ソース情報・追加ソースは IPA の ThirdPartyNotices に収録する。

Actions の `checkpoint-trial` は device/simulator ビルドと、この診断画面の
8bit/10bit 長 GOP 素材による検証に絞る。シミュレーターの成功は iPhone の速度や
熱・電力の成功を意味しない。実機での診断結果を比較してから通常再生への採用を判断する。
