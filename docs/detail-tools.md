# 録画詳細の開発用ツール

参照: Webの`RecordedSubtitleTransferPage.tsx`、`RecordedItemActions.tsx`、`core/api/queries.ts`、API型定義、サーバーの`VideoApiModel`と対応ルート。プレイヤー描画・復号・配信処理は変更しない。

| Webの仕様 | iOSの対応 |
| --- | --- |
| developerMode時だけ詳細に入口・ページを表示 | メニューの既存条件を維持。ページを開く際にもconfigを確認し、無効ならデータ取得・変更操作を出さない。サーバーのモード検査も維持。 |
| 2ペイン、左は元の録画と最初のMKV、右は未選択 | 番組名/局名検索、録画選択、MKVファイル選択。1200px未満は縦並び、以上は横並び。 |
| 検索は30件ずつ・局名のNFKC一致も検索 | タイトルと一致局を取得し、重複排除・新しい順に結合。追加読込に対応。同時取得は最大4件。 |
| 一覧の名前、codec、language、default/forced | 同じAPIの`subtitleIndex`を操作に使用。`streamIndex`と区別する。 |
| 別のMKVへ移植、名前変更、上下で並び替え | 同じPOST/JSONを送信。名前は前後空白を除去し128 UTF-16単位まで。移植予定は1件。順序は全トラックの変更済み順列のみ。 |
| 保護・処理中・MKVなし・空・読込失敗 | 保護警告とサーバーの拒否理由、読み直し、無効状態を表示。実行直前に元トラック一覧も再取得して表示時点との差異を検知する。 |
| 非同期タスクの1秒ごとの状態確認 | 受付後はAPIが状態確認を所有。ページを閉じてもサーバーは継続し、アプリ内では完了後に録画キャッシュを更新する。中止APIは存在しないため、取り消せるような表示はしない。 |
| 完了/失敗後の再取得 | 完了時に両ペインの一覧、録画済み・詳細・履歴を更新。状態取得だけが失敗した場合は既知のIDでGETのみ再試行し、POSTを繰り返さない。 |

意図した差異: Webでは処理中に選択を変更するとローカルのタスク状態を消すが、アプリは開始済み処理の追跡を続ける。移植先を後から選び直しても、受け付け済みの操作対象を変更しない。アカウント/接続先が変われば旧コンテキストの操作・UI反映を停止する。

検索はネイティブ入力欄と候補一覧で構成し、Webと同じく候補一覧の末尾48pt以内へのスクロールで追加取得する。VoiceOverでは追加読込ボタンも使用できる。入力中のキーボード・カーソルを保持し、名前/移植後の名前の編集は候補の更新で作り直さない。画面は遷移開始後に構築する。

検証範囲: `player-feedback` / `detail-tools`。Foundationのモデル/API試験とiPhone・iPadの対象画面の試験に限定する。模擬データだけを使用し、実サーバーの録画ファイルを書き換えない。サーバー内部の再多重化成功・実機での最終確認とは区別する。

## 入力・復帰時の修正

- 検索候補のタイトル/局名用スタックはタッチを受け取らず、候補ボタン全体で選択する。候補一覧内のタッチ遅延も無効にする。
- アプリ復帰時の認証再確認中は選択・編集内容を維持して操作を一時保留する。同じ接続先・ユーザー・プロフィールで認証が戻った場合は、新しいセッションで読み直し・処理状態の監視を再開する。実際のユーザー/プロフィール変更時は旧画面を無効化する。
- 再確認前の読み込みはキャンセルし、初期読み込みと処理監視の遅延応答も認証世代で除外する。認証再確認による変更操作のPOST再送は行わない。
- 回帰確認では表示文字/余白のヒットテストから候補ボタンへ到達することと、同一ユーザーの一時保留・再開、別ユーザーへの切り替えを検証する。
