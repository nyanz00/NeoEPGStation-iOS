# ローカル動画のGOPシーク測定

## 成功条件

エーテルの通常の`NeoPlayerController`で音声付きローカル動画を前面再生し、共通の絶対時刻への送り・戻しを測る。別の復号専用プレイヤーは作らない。元の再生エンジン・チェックポイント・字幕・コメントのグローバル設定は変更しない。測定セッションではチェックポイントを無効にし、字幕・コメントなし・等速・横画面を基準とする。履歴・Annictへの書き込みは行わない。

設定→視聴→GOPシーク測定（ローカル）から、PCで生成した測定計画JSONと動画を「ファイル」でまとめて選ぶ。動画はアプリの領域へコピーされるため空き容量が必要。コピーと初期読み込みの時間はシーク時間に含めない。計画に記録したファイルサイズで対象を照合し、再生時にも長さを確認する。ファイルサイズは暗号学的同一性の証明ではない。実ファイルのパスや番組名を結果へ書かない。

`python scripts/gop-plan.py <動画フォルダー> <出力JSON> --ffprobe <ffprobeの実行ファイル> --ffmpeg <ffmpegの実行ファイル>`で生成する。パケットのキーフラグとPTSから前方キー時刻を記録し、平均FPSも保存する。測定位置・準備位置の周辺±2フレームを32×18の輝度画像として計画へ入れる。キーフラグ自体の正しさはコンテナ・映像データに依存する。私的な動画の解析結果・画像はアプリへ同梱・コミットしない。

## 測定手順と時刻の意味

- 共通の24シーク先を使用。各位置へ約10秒前・10秒後から移動し、1周48測定。方向の先行順を交互にし、周回でも反転する。1〜3周を選べる。動画の順序は開始時にランダム化し、結果の順序として保持する。
- 最初に2測定をウォームアップとして記録するが集計から除く。各測定前の準備用シークも集計しない。準備位置の映像を確認して300ms再生してから、測定シークを通常コントローラーの経路へ渡す。送り戻し距離は再生継続分があるため厳密な10秒にはならず、実際の開始位置を保存する。目的位置は全動画で同じ。
- 操作関数の呼び出しから、目的PTS±2フレーム（最低30ms）以内の映像バッファを確認するまでを`displayMs`とする。エンジンのseek戻りは`engineCompletionMs`として別に記録する。画面の物理的な発光を測る光学試験ではない。
- ソフトウェア経路では表示済みsurfaceのsource PTS、AVPlayer経路では現在item時刻の表示用バッファを確認する。検証方法を各行に記録する。表示時刻未確認の画像は成功や高速サンプルとして集計しない。ポーリング間隔は約16.7msで、フレーム周期も含む測定の時間分解能を考慮する。
- 表示サービスがsource PTSを除去する環境では、シーク後の世代で目的位置が復号された通知を受けたうえで、実際の表示済みバッファと計画の画像を照合する。MAE 9/255以内・相関0.985以上を要求し、開始前の画像でも一致する場合や平坦な画像は曖昧として集計から除く。これは近似画像照合であり、表示タイムスタンプの直接取得とは区別する。結果は`referencePTS`と`displayed-picture-reference`を記録し、キューの時刻を`picturePTS`へ書かない。読み戻しの負荷も測定時間へ含み、その累計を併記する。
- 実キー時刻・キーからの距離、実際の再生経路、画面寸法、温度状態、方向・周回を記録する。通信時間はローカル化で除外するが、ファイルI/O、OS・エンジンキャッシュ、音声同期、描画は含む。
- 手動操作・中断・前面から外れた場合・PiP・再生停止や復旧では中断する。途中結果を保存し、失敗を成功に含めない。準備映像を確認できない場合も測定を続行しない。
- 保存ごとに原子書き込みし、`gop-seek-current.json`と完了済み動画の集約`gop-seek-benchmark.json`を共有できる。中央値・90%点・最遅値・平均と試行数/成功数を全体と方向別に残す。

## 検証範囲

Foundationの試験で計画の検証、キーの前方探索、共通ターゲット、方向の均衡、失敗除外と統計を確認する。両SDKをビルドし、シミュレーターでは既存の音声付きAV1動画を使い、実際の通常プレイヤーでウォームアップ2回・測定6回を行う。目的PTS、エンジン通知との分離、途中/最終JSON、前面再生の画像を確認する。これはiPhone実機の性能値とは扱わない。

初回はUIKitの継承プロパティとの名前衝突を修正。続く実再生試験で、表示済みバッファのCVBuffer添付情報・IOSurface値の両方が失われることを確認した。取得成功と見なす条件を緩めず、表示画像の参照照合を追加して再検証する。画像照合は測定セッション限定で、通常再生には追加しない。

参照画像の縮小はCore Imageに合わせてリニア光で行い、sRGBへ戻して輝度化する。色行列はBT.709を指定する。SDRの未指定バッファの解釈差を扱うため、sRGB/BT.709転送特性の参照を区別して保持する。既存のシミュレーター画像で、ガンマ符号化されたYUVの縮小ではMAE約19・相関約0.96だったものが、対応する色変換ではMAE約6・相関約0.986となることを確認した。照合閾値は変更しない。参照生成・試験だけの修正は、アプリソースと依存の同一性を検証した上でビルド済みバイナリーを再利用する。
