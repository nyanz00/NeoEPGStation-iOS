# 一時停止後の状態維持と中断位置からの起動

## 変更

- 一時停止中にバックグラウンドへ移っただけでは、キャッシュのリスナー・読み取り接続を切断しない。VLCの入力、解析情報、復号状態、停止位置を維持する。
- 通常の復帰は映像の配置と最新の再生／停止意図を反映し、入力URLとVLCMediaを再作成しない。通常の映像表示面も、復帰だけで画像とキューを消去しない。AVレンダラーが失敗した場合のみリセットする。
- 接続障害やVLC入力の失敗で開き直す場合は、メディア作成時に`:start-time`で保存時刻を指定する。`:start-paused`で準備し、初期バッファの準備と初期一時停止の確定後に最新の再生／停止意図を反映する。先頭の再生を準備に使った後で保存位置へシークする経路は廃止する。
- VLCの開始時刻指定は入力の時間と長さの基準を変えるため、アプリは元ファイルの時間へ換算する。コメント、PiP、操作欄、ロック画面、履歴、保持キャッシュも同じ元ファイルの時間を使う。
- 入力の開き直し直後に、VLCの補間時刻が一瞬だけ大きく跳ねるケースを合成動画の診断で確認した。動画の長さを超える時刻と、初期化直後の不合理な前進は最後の正常時刻で保持し、コメント・履歴・キャッシュへ渡さない。明示的なシークは初期化直後の前進制限を解除する。異常値の記録は入力ごとに一回までにする。
- 時刻指定のシークは、元ファイルの目標時刻を入力の相対時刻へ換算して直接設定する。相対移動の補助メソッドが内部でVLCの補間時刻を読み直して目標を変えてしまう経路を避ける。索引のないTSの位置指定による代替処理は維持する。
- 開き直した入力の開始位置より前へ移動する場合は、その移動先を開始位置にして再作成する。通常の状態維持による復帰では開始位置は変わらず、この再作成は不要。
- バックグラウンドで実際に入力が失敗した場合にも、ユーザーの再生／停止意図と中断位置を失わせない。復旧の期限とキャッシュ終了時の清掃は維持する。
- 復旧入力の準備開始を記録し、遅れて届いた旧入力の停止通知で同じ復旧入力を再作成しない。現在のVLC状態と一致しない停止・エラー通知も無視する。
- 初回のコメント・接続準備中に押された再生ボタンは、準備待ちを復旧処理で迂回しない。最新の再生／停止意図を保持して、準備完了後に適用する。

Web側の`RecordedPlayerCore.ts`の停止、再生位置、TS HLS再読み込みの処理を確認した。今回の変更はネイティブVLCとiOSライフサイクルの経路に限定し、サーバーのAPIやWeb側は変更していない。

## 実機確認の範囲

OSが一時停止中のアプリを休止・終了した場合や、ネットワーク接続を失効させた場合まで、接続維持を保証するものではない。シミュレーターのライフサイクル試験と実際のiPhoneのロック・休止は区別する。実機では停止してロック／ホーム移行、復帰、再開、巻き戻しを確認する。

ファイルのヘッダー、索引、復号開始に必要なデータの読み取りは残る。開始時刻指定を入れたことだけで、すべてのファイルで通信量が一定量減ったとは扱わない。
